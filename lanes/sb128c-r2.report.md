## TASK A — root cause

`crates/ec-av1/src/decode.rs:18713` (`decode_inter_block`'s intra tail) read
`cdfs.uv_mode_cfl[mode]` **unconditionally**. libaom `read_intra_block_mode_info` calls
`read_intra_mode_uv(ec_ctx, r, is_cfl_allowed(xd), bsize)` and `is_cfl_allowed`
(`~/.cache/aom-oracle/src/av1/common/blockd.h`) is
`block_size_wide[bsize] <= 32 && block_size_high[bsize] <= 32`. So any intra block 64 px or wider
inside an INTER frame must read the 13-symbol `uv_mode_no_cfl` alphabet. Reading the 14-symbol CFL
one yields the same VALUE from a different interval — class `wrong-alphabet-same-value`. Fix:
`let cfl_allowed = write_w.max(write_h) <= 32;` then the two-branch read (the split every other
`uv_mode` reader in the file already makes: `decode.rs:5521`, `6203`, `8500`).

Method (charter's ladder, RANGE never `tell()`):
1. `EC_TRACE_MODE=1 EC_TRACE=1 aomdec g8.obu` vs ours; `EC_MODE` ranges agree block for block until
   the 64x64 block at mi (0,32) of an inter frame.
2. Added the pre-read range to our `partition_w64` trace: entry rng **61470 == aomdec 61470**; the
   NEXT partition (mi (0,48)) is **ours 35887 vs aomdec 54271** → the divergence is inside that block.
3. `EC_AV1_TELL` bit ladder: the block spans tell 170→192 in ours, 154→173 in aomdec (same 16-bit
   constant offset at entry) → **we over-read ~4 bits**; `is_inter=0 skip=0 side=64` on both sides,
   so it is the intra tail, and the only symbol whose alphabet depends on the 64-px size is `uv_mode`.
4. After the fix the ladder tracks through this block and every later one, up to a real new stop.

EVIDENCE: `$HOME/.cache/sb128c-work/{aomdec.all,ours.trace}` | `EC_TRACE/EC_TRACE_MODE/EC_TRACE_COEFF` aomdec vs `EC_AV1_TRACE/EC_TRACE_MODE/EC_AV1_TELL` decode_probe on `g8.obu`, both under `systemd-run --scope -p MemoryMax=6G` | **partition rng at mi (0,48): 35887 → 54271 (== aomdec) after the fix; refusal moves from "a split intra strip whose transform unit is 32x64" to a shape aomdec confirms exists**
