# lane/h264hi10 (second pass): bit depth >8 audit, FMO and ASO

## Audit
High 10 (4:2:0, 9/10-bit), High 4:2:2 (8/10-bit), their PAFF/MBAFF variants, 4:4:4, monochrome, lossless and 14-bit (`set_wide_samples`) were already decoded on main, byte-exact vs ffmpeg (tests/high10.rs, high422.rs, high422_jvt.rs, mbaff_x264.rs with `-flags +ildct`, CABAC and `-coder 0`). Nothing in that area was missing, so no change there. Output formats unchanged (I010/I210/I422/I444/I410).
Still refused by name: SP/SI, data partitioning, FMO with interlaced coding, 4:4:4/depth combos already named (differing luma/chroma depth, depth above 10, or above 14 with wide samples).

## Done: FMO and ASO (Baseline/Extended)
- `src/fmo.rs`: macroblock-to-slice-group map, clause 8.2.2, map types 0..6; `next_in_group`.
- decoder.rs: slice loop steps through the slice group; `slice_group_change_cycle` taken from each slice header; FMO refused only when `frame_mbs_only` is 0.
- ASO: refusal removed. Neighbour availability was already per slice id, deblocking runs at picture end. A new picture is detected by the 7.4.1.2.4 header key (also for a first slice that is not MB 0), or by MB 0 arriving again; a late slice 0 within the same picture is no longer taken as a new picture.
- Slices with `redundant_pic_cnt > 0` are skipped (primary data is used).
