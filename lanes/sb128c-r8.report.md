## What changed

- `crates/ec-av1/src/decode.rs:10101` `decode_block_128rect` (NEW): a rect
  intra block at the 128 root. libaom `decode_block` ->
  `predict_and_reconstruct_intra_block` per transform unit, with the 128
  geometry: `max_txsize_rect_lookup[BLOCK_128X64] == TX_64X64` so every luma
  unit is SQUARE and there are >= two (depth 0: 64x64 x2, 1: 32x32 x8,
  2: 16x16 x32 -- `bsize_to_tx_size_cat` counts the `sub_tx_size_map` chain
  TX_64X64->32->16->8->4, i.e. cat 3, the CDF a 64x64 square block reads);
  `av1_get_max_uv_txsize` = `av1_get_adjusted_tx_size(
  max_txsize_rect_lookup[BLOCK_64X32])` caps at TX_32X32, so the 64x32 uv
  plane block is TWO 32x32 chroma units per plane, one per 64x64 "mu" chunk,
  Y then U then V inside each chunk (`decode_token_recon_block`);
  `get_txb_ctx` puts chroma on the offset-10 rows (uv plane block > uv tx).
  Mode info goes through `read_intra_mode_rect` with `cfl = false`
  (`is_cfl_allowed` caps at 32x32); filter intra and palette do not exist at
  this size (`av1_filter_intra_allowed_bsize` 32x32,
  `palette_bsize_ctx_wh` returns `None` above 64) and are refused by name if
  one ever appears. Per-TU edge availability through `tu_reach`
  (`has_top_right` false for a block whose long side is > 64, via
  `Reach::of_rect`); lf/skip grids stamped with the resolved unit size.
- `crates/ec-av1/src/decode.rs:14027` key-frame path: the 128 root's
  HORZ/VERT arm is no longer refused. It decodes `BLOCK_128X64` at
  (mi_row, mi_col) plus a second at (mi_row + 16, mi_col) only
  `if (mi_row + hbs < mi_rows)` (VERT mirrors it on the column, libaom
  `decode_partition` decodeframe.c:1554), each half reading its OWN
  `cdef_idx` literal, fanned out over the 64x64 CDEF units it covers.
- `crates/ec-av1/src/decode.rs:9346` / `:9247` `PlaneBuf::reconstruct` +
  `reconstruct_rect`: bottom/right frame-edge CLIP. ROOT CAUSE of two
  `index out of bounds` panics on the 1080p film's key frames (len 1536000,
  index 1536000/1536384): our frame buffer is padded to 32 (`block_grid`)
  while libaom's is superblock aligned, so a 64x64 unit of a 128x64 block at
  y=768 of a 792-row frame wants 832 rows of an 800-row buffer. Those samples
  are outside the frame -- never output, never referenced.
- `crates/ec-av1/src/stream.rs:95` `intra_sb128_counters()`,
  `crates/ec-av1/src/decode.rs:10101` `INTRA_SB128_{HORZ,VERT,DEPTH}_HITS`.
- `crates/ec-av1/src/refusal_inventory.rs:48`: the intra-128x64 refusal is
  REPLACED by the defensive CfL/filter-intra/palette one.
