## 2. Root-cause fix: the 128 root threw its own partition symbol away (`e3d32d1`)

`decode.rs::read_sb128_root`, half-out-of-frame arm: it read the gathered
2-symbol `split_or_horz`/`split_or_vert` and returned `PARTITION_SPLIT`
unconditionally. Spec 5.11.4 makes that symbol the DECISION (1 = SPLIT,
0 = HORZ when only cols are out / VERT when only rows are out). The 64 root
`partition_w64` already carries the fixed form -- its own comment records the
3840x1608 10-bit head this same defect desynced -- so this is that class
(`parsed then discarded`) unported to 128.

Consequence before the fix: a 128 root that really codes HORZ/VERT at the
frame edge was silently reconstructed as a split instead of reaching the
refusal that names it. Found because the converted oddh gate decoded
pixel-exact while reading zero 128 partition symbols.

New witness counter `part128_gathered_symbols()` (`decode.rs:89`), asserted
`> 0` by the oddh gate. Its recipe also gains `--min-partition-size=16`:
without it aomenc emits `PARTITION_HORZ_4` below 16x16 (another lane's gap)
and the gate measured that refusal instead of the 128 root.

`decode_probe` now prints `SEQ: use_128x128_superblock=... bit_depth=...
max_frame=WxH` next to its tiling line.
