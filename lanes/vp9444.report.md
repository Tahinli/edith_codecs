## Root cause / design

The crate already stored planes as `u16` with a single decode walk and
`clip_pixel_bd`, and the HBD/inter lanes had already parameterized MC, the
intra predictor and the transform by `(ss_x, ss_y)` in the places the oracle
needed them. The remaining hardcoding was a single idiom repeated in ~20
sites: `let s = usize::from(plane != 0)` — every plane-geometry shift, the
n4 block counts, the chroma transform size, the crop extents, the chroma
sub-block MV averaging and the loop-filter plane dispatch assumed 4:2:0.

The port threads the frame's real `subsampling_x`/`subsampling_y` through, per
libvpx 1.15:

- `Planes` gains `ss_x`/`ss_y`; chroma is `aw >> ss_x` by `ah >> ss_y` (the
  aligned extent is a 64-multiple so the shift is exact) and `dims()`/crop use
  `(w + ss_x) >> ss_x` (`uv_crop_width`).
- `plane_ss(hdr, plane)` replaces `usize::from(plane != 0)`; every `>> s` /
  `<< s` / `(5 + s)` splits into its `ss_x` / `ss_y` axis.
- `pd->n4_w/h` = `(bw << 1) >> ss_x` (`set_plane_n4`).
- `get_uv_tx_size` becomes the real `uv_txsize_lookup[sb_type][tx_size][ss_x]
  [ss_y]` (new `UV_TXSIZE_LOOKUP`, 208 entries, extracted verbatim from
  `vp9_common_data.c`); `ss_size` keeps its `ss_size_lookup[bsize][ss_x][ss_y]`
  form and now also backs libvpx's `BLOCK_INVALID` corrupt-frame check for
  `bsize >= 8x8` under any subsampling.
- `average_split_mvs` (mc.rs) selects by `ss_idx`: luma/4:4:4 own sub-block MV,
  4:4:0 the q2 vertical pair, 4:2:2 the q2 horizontal pair, 4:2:0 the q4
  average over four.
- Entropy contexts: the above arrays are now `2 * mi_cols_aligned_to_sb` for
  EVERY plane (libvpx sizes them so: `2 * mi_cols_aligned_to_sb * MAX_MB_PLANE`),
  because a 4:4:4 chroma block indexes the same span as luma.
- Loop filter (`filter_frame`) dispatches exactly like `vp9_loop_filter_frame`
  (vp9_loopfilter.c:1430): luma and 4:4:4 chroma through
  `filter_block_plane_ss00` (4:4:4 chroma reuses the LUMA masks AND luma filter
  levels — `lfm->lfl_y`), 4:2:0 chroma through the existing `ss11` pass, and
  4:2:2 / 4:4:0 through a new `filter_non420_plane` port of
  `vp9_filter_block_plane_non420` (masks + `get_filter_level` built inline per
  superblock band).
- 12-bit: the only depth-dependent syntax element is the CAT6 token; 12-bit
  needs the FULL `vp9_cat6_prob_high12` with 18 bits (`vp9_detokenize.c:137`),
  not the 16-bit `+ 2` view 10-bit uses. New `CAT6_PROB_HIGH12[18]`; the
  `decode_coefs` branch is now `8 => 14 bits / 10 => 16 / 12 => 18`.

## Byte-exactness (milestone 3)

`$HOME/.cache/vp9pix/sweepss.sh <worktree> <stream>`: libvpx-oracle dump vs our
`scratch_pixdump10` dump (both u16 LE), `cmp` (no parser). Our side dumps only
SHOWN frames; the oracle dumps only shown frames too, so a hidden frame would
show as a size mismatch, not a silent pass.

Non-vacuity for the loop-filter port: with `EC_VP9_SKIP_LF=1` (ours) and
`SKIPLF=1` (oracle) the 4:2:2 / 4:4:0 streams were IDENTICAL on the first
non420 cut, which localized the first divergence to the new
`filter_non420_plane`; after the fix the full-filter dumps match. (The bug was
the horizontal `filter_selectively_horiz` gating: a 16-tap block edge swallows
the internal 4x4 edge, the 8-/4-tap branches emit it separately, and an
internal-only bit takes the else branch.)
