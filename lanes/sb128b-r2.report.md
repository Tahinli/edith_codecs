## TASK A — the chroma half of a 128x128 `PARTITION_NONE` block (landed, not yet exact)

`crates/ec-av1/src/decode.rs`
- `decode_block`'s multi-TU arm now codes `cn = chroma_side / chroma_tx` **squared** chroma units
  per plane instead of one whole-plane unit. `av1_get_max_uv_txsize(BLOCK_128X128)` =
  `av1_get_adjusted_tx_size(max_txsize_rect_lookup[BLOCK_64X64])` = TX_32X32, so a 128 block is
  2x2 TX_32X32 per plane; `cn == 1` (every block at 64 and below) is byte-for-byte the read this
  always did. Per unit: `around_mi` gathered over the unit's own 64-luma-pixel span (which is
  also its `txb_skip_ctx`, `read_plane`'s chroma branch), `tu_reach` on the matching luma
  quadrant, own `set_palette_pred`.
- `Neighbours::record_mi_chroma` (new, next to `record_mi_luma`): per-unit chroma coefficient
  context, luma-mi indexed with `record_split_luma_rect_mi`'s own frame-edge clamp. Applied
  AFTER `record_split_luma` so the per-unit state is what the next block reads.
- The `skip` arm predicts per transform unit now (libaom predicts inside the transform-block
  loop); `n_axis == 1` / `cn == 1` is the unchanged whole-block call.
- counter `chroma_split_tx_hits()`.
