## 2. Defect found and fixed: `-ss 300`, 463 bytes → 0

Re-measured premise on this branch (1-frame truncation, hash stable twice):
U 219 / V 220 samples wrong, Y exact. `EC_AV1_PREFILT_DUMP16` ours vs aomdec's:
227 U + 227 V wrong **before the loop filter**, in a 16x16 chroma region at
chroma `(384,412)` — reconstruction, not filters.

First bad sample chroma `(412,384)` = the 4x4 chroma block of the `BLOCK_4X4`
2x2 group at luma mi `(206,192)`. aomdec `EC_TRACE_MODE`:
`EC_IMODE_VAL mi_row=207 mi_col=193 mode=4 uv_mode=13 skip=1` — `uv_mode = 13`
is `UV_CFL_PRED`, `skip_txfm = 1`. Our `OUR_PRED x=384 y=412 side=4 mode=0
sum=8240 row0=[515,515,515,515]` is flat: DC with **no CfL term at all**
(aomdec's own prediction sums to 8241 with a bottom-left ramp).

Root cause: both sub-8x8 leaf decoders passed a literal `None` for the CfL
argument in their `skip_txfm` arm —

- `crates/ec-av1/src/decode.rs:10554/10555` (the 4-leaf `BLOCK_4X4` group)
- `crates/ec-av1/src/decode.rs:10916/10917` (the 2-leaf group)

libaom's `av1_predict_intra_block_facade` (`av1/common/reconintra.c:1719`) calls
`cfl_predict_block` whenever `mbmi->uv_mode == UV_CFL_PRED`; `skip_txfm` only
suppresses the residual, never the alpha. Both arms now compute
`cfl_ac_q3(y, gpx, gpy, 8)` and pass `alpha.zip(ac)`, exactly like the
non-skip arm two lines below and like the rect skip arms already did.

### Class sweep

Every chroma `reconstruct` / `reconstruct_rect` call site in `decode.rs` was
parsed and its cfl argument printed (script in the r2 scratchpad). The rect
skip arms (`6015`, `6519`, `8078`) already pass `alpha.zip(ac)`; the only other
literal `None` is `20284/20296`, which sits directly behind the refusal
"a non-DC chroma mode on an 8x8 inter-frame leaf" (`decode.rs:20212`), so
`uv_mode == DC_PRED` is guaranteed there. No other instance of the class.

### Counter + gate

- `decode.rs:2207` `SKIP_CFL_HITS` / `pub fn skip_cfl_hits()` — skipped sub-8x8
  chroma blocks that carried a CfL alpha.
- `crates/ec-av1/src/stream.rs`
  `the_hunger_games_ss300_key_frame_skipped_cfl_decodes_pixel_exact` — pins
  `crates/ec-av1/fixtures/hg_ss300_key_frame.obu` (139 201 B, sha256
  `7e3ddf0d602f9496b2f7eb11f051fd4a045020e094d5bc02f83825e2c494ef12`, one
  3840x1608 yuv420p10le key frame), decodes it, HARD-asserts
  `skip_cfl_hits > 0`, then compares Y/U/V against ffmpeg's own 10-bit decode.
  `git add -f` was used (bare `fixtures` in .gitignore); `git ls-files` confirms
  it is tracked.

Why a fixture and not an aomenc recipe: lane-troykf r1's ledger dead-end —
20 recipes (cq 40..63 × nine lavfi sources, min/max-partition sweeps, sb-size
64 and 128) never produced a **skipped** sub-8x8 CfL block (`skip_cfl` counter
0 in all). The shape fires exactly **once** in a whole 4K key frame, which is
why no synthetic source reaches it.

No refusal lifted → `refusal_inventory.rs` / `gate_coverage.rs` unchanged.

## 3. Remaining residuals — triaged, one class

`-ss 600 / 2400 / 3300 / 5700` (48771 / 42343 / 39971 / 16375 bytes) are ONE
defect class, not four: in every one of them the damage is confined to the
**last 8 luma rows** of the frame.

| -ss | Y rows wrong | U/V rows | first bad Y sample |
|----:|---|---|---|
| 600 | 1595..1607 | 796..803 | (1595, 2916) |
| 2400 | 1595..1607 | 796..803 | (1595, 2445) |
| 3300 | 1595..1607 | 796..803 | (1595, 1235) |
| 5700 | 1596..1607 | 796..803 | (1596, 3039) |

`EC_AV1_PREFILT_DUMP16` on `-ss 600` narrows it further: pre-loop-filter the
damage is exactly rows **1600..1607**, columns **192..3839** (rows 1595..1599
in the final picture are deblock spill across the y=1600 edge). The frame is
1608 rows = 25 full 64-px superblock rows + one 8-row remainder, so this is the
bottom **partial** superblock row, and the first three superblocks of it
(columns 0..191) are pixel-exact.

Divergence localised to a single block. Through luma mi `(400,47)` our
prediction trace matches aomdec's block for block (mi 44: four TX_4X4 in an
8x8; mi 46: 8x8 — `EC_PRED mi_row=400 mi_col=46 txw=8 txh=8`). At the very
first block of superblock #3:

- aomdec: `EC_PRED mi_row=400 mi_col=48 txw=16 txh=8 mode=2 p_angle=180 bsize=5 part=1 ft=1`
- ours:   `OUR_PRED x=192 y=1600 bw=32 bh=16 mode=0 ad=0` (decode.rs:6511)

i.e. we read a 32x16 `PARTITION_HORZ` where libaom reads a 16x8, and the mode
differs too — a **partition-symbol divergence at the root of a partial-height
superblock** (`has_rows == false`, only 2 of 16 mi rows present), not a
prediction bug and not caused by the preceding block. Everything after it in
that row is garbage because the row never re-syncs (it is the last row, so
nothing propagates downward).

`-ss 4800` (2348 bytes in r1, **34 bytes** after this round's CfL fix) is a
different, much smaller shape: chroma only,
U 29 + V 5 samples in the final picture. `EC_AV1_PREFILT_DUMP16` puts it
**pre-loop-filter** too — U 25 + V 3 samples in an **8x4 chroma patch** at
rows 540..543, cols 1200..1207 (`|d| <= 6`), luma exact. That is the same
geometry as r1's defect (an 8x4 chroma block = the chroma half of a 16x8
`PARTITION_HORZ_4` pair) at luma mi ~`(270,600)`, so it is a strong candidate
for a sibling of the pair-mi bug rather than a new class.

## 4. Disposition

- fix-now (done): `-ss 300` skipped-CfL, fixed + gated + swept.
- deferred: the bottom partial-superblock partition divergence (`-ss 600`,
  2400, 3300, 5700). Unblocked by: a range ladder over the partition symbols
  of superblock `(mi_row=400, mi_col=48)` in `s600_f1.obu` comparing aomdec's
  `r->ec.rng` at `EC_IMODE` against ours — the first three superblocks of the
  same row are exact, so the ladder starts already in sync at mi 400/47.
- deferred: `-ss 4800` (34 B, down from 2348) — stage-attributed (pre-loop-filter, chroma-only,
  8x4 patch at chroma (540,1200), luma mi ~(270,600)); the per-block
  `EC_IMODE_VAL`/`EC_PRED` comparison at that mi is the next step.
- accepted: `-ss 900 / 1500 / 2100 / 2700 / 3900 / 6000 / 6300 / 6600`
  (multi-million bytes) are lane-kf900's entropy desyncs, not merged into main.
