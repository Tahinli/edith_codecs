## What changed (this continuation, on top of the staged WIP commit)

1. `decode_block` single-TU arm (was the prior agent's unstaged edit,
   debug prints removed): at 4:4:4 a 64x64 block's chroma is coded as
   four TX_32X32 units plane-major — confirmed bug-for-bug against
   libaom `av1_get_max_uv_txsize` (`av1_get_adjusted_tx_size`,
   blockd.h:1361) and the plane-major unit loop in
   `decode_token_recon_block` (decodeframe.c:970-1010).
2. **Root cause of the 36k chroma diffs** (the prior agent chased a
   phantom 64x64 block — the stream has none): `u`/`v`
   `set_tile_origin` hardcoded the 4:2:0 halving (`mi * 2`). At 4:4:4
   the halved `tile_x1` clamped `PlaneBuf::edges`' `across` below the
   block's own x for every chroma block in the right half of the tile
   (and `tile_y1` the left edge in the bottom half), so those blocks
   predicted with edges missing (left-only/above-only DC). Localized by
   proving the entropy ladder identical (1596/1596 rng rungs vs the
   instrumented aomdec), then diffing `OUR_PRED`/`EC_PREDOUT8` for the
   first divergent CFL block: aom DC 129, ours 145, traced to
   `above=None` in `edges()`. Tile bounds now `mi * 4 >> ss`; identical
   at 4:2:0.
3. Loop filter: `deblock_plane_span` clipped chroma to
   `frame_width/2 × frame_height/2` (another hardcoded halving) — at
   4:4:4 the filter never touched three quarters of each chroma plane.
   Crop now follows `ss`. (CDEF and restoration were already exact:
   isolating arms `--loopfilter-control=0` vs `--enable-cdef=0` /
   `--enable-restoration=0`.)
4. Rect/1:4 4:4:4 port (in progress):
   - `decode_block_rect4` (32x8/8x32 strips): chroma table was
     hardcoded 4:2:0 (`Chroma8`, SCAN_16X4/4X16, mode-derived tx_type
     with no size clamp → ADST-at-32 panic). Now shape-keyed
     (4:4:4: `Chroma16`, SCAN_32X8/8X32) with the
     `av1_get_ext_tx_set_type` DCT_ONLY clamp at square-up ≥ 32
     (blockd.h:1278).
   - Inter rect chroma: a 64-axis strip at 4:4:4 keeps its 64-px chroma
     axis, capped to 32-wide units (`av1_get_max_uv_txsize`), so it
     codes TWO units plane-major. New `read_inter_rect_chroma` helper
     (both `decode_inter_block` rect readers call it);
     `read_inter_plane_rect`'s chroma skip_ctx takes the +3 (libaom
     +10) offset for multi-unit blocks; `rect_inter_chroma_set` gained
     the (32,32) → `Chroma32` entry.
   - `decode_rect4_16_strip` (16x4/4x16 strips): at 4:4:4 there is no
     4:2:0 chroma pair — every strip is its own chroma reference
     (`is_chroma_reference`: no mi-parity test at ss 0/0, strip's own
     chroma ≥ 4x4). `has_chroma` is now true for every strip at ss 0/0
     (key-frame caller `decode_rect4_16` AND the inter
     `inter_strip_chroma` construction), the pair origin/tables/CfL
     window anchor at the strip itself, and the inter `prev`
     (both-strips MC) is disabled at 4:4:4.
   - Leftover instrumentation from the staged WIP removed (EC_64*,
     EC_TILE); `EC_RECTCHROMA_GAP` stays (deliberate diagnostic per its
     comment).
