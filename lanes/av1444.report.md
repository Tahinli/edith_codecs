## Exact divergence

First profile-1 block is an 8x8 leaf at mi (0, 0). Before the leaf fix that
leaf read 4x4 chroma, under-consumed symbols, and luma diverged at pixel 8.
After the fix, luma of both frames matches and U/V match until x=112.

x=112 sits inside the 64x64 block at pixel (64, 0) (`EC_BLOCK side=64
at=(0, 4)`, `chroma_in=32`). That block takes `decode_block`'s
`logical_tx == side` arm (side 64, one luma TU whose coefficient grid is
32). The arm then reads **one** chroma unit with reconstruct side
`chroma_side` (64 at 4:4:4) and coeff tx `chroma_tx` (32). libaom codes
**four** TX_32X32 chroma units for a 64x64 uv plane block at 4:4:4
(`av1_get_max_uv_txsize` of a 64x64 uv bsize is TX_32X32, 2x2). The
multi-TU arm already loops `cn = chroma_side / chroma_tx` units, but a
64 block never enters it because `logical_tx == side`. Comment is on the
U `read_plane` in that arm.

Quadrant diffs inside that 64x64, U plane, frame 0: (0,0) 764/1024,
(1,0) 896/1024, (0,1) 973/1024, (1,1) 1024/1024. Row 0 of the block matches
for the first 48 samples, then goes flat-wrong. That is a wrong chroma
unit, not a luma desync.
