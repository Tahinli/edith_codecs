r5's premise is DISPROVED: it is not intra-in-inter and not CfL -- `EC_PRED=1`
on the same run emits NO intra prediction at that chroma position (nearest is

The 4x4 U difference (aomdec minus ours):

    [ +4  +5  +6  +8 ]
    [ -1   0  +3  +6 ]
    [ -5  -3   0  +5 ]

differing => the msac stream is in sync and only the inverse transform's BASIS
is wrong. Class `tx-type-set-membership` (chroma of an inter block inherits the
colocated luma `tx_type`; a wrong pick inside the same TX_CLASS leaves the
range identical). `reduce_inherited_chroma_tx_type` (decode.rs:14794) and
`read_inter_luma8`'s top-left rule (decode.rs:14700) were read and look correct
for this shape, so the decisive step is the ORACLE, not another code read:

(`scripts/build-aom-oracle.sh` -- incremental), and diff the one line for this

prints no value -- add it there too). If they agree, the next suspect is the
