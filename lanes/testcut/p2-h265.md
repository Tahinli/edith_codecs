Status: DONE (second attempt, host b, lanes `testcut-p2-h265-s1`, `-s2`). Deleted 3 tests, about 317 s of release runtime saved (per rest.tsv times: 143.0 + 54.7 + 119.2). ffmpeg_decodes_bit_exactly_at_every_shape was restored after the recheck below.

## Method and why the first attempt was invalid
The earlier "kills" were timeouts: mutation runs used the debug profile, so the unmutated pixel run took 915 s against a 429 s timeout. This run uses `--release` everywhere, builds each mutant first (`--no-run`, separate build timeout), and sets the test timeout to 2.5 x the measured unmutated baseline of the same command on the same host (`run1.sh`, `fast.sh`, `mutrun.py`). Mutants are applied by index from `mutants.json`, 10 seeded (seed 2026) mutants per candidate from U(T) functions (noisy: functions T covers). A kill counts only if the test failed (rc=100, tests ran); timeouts do not count. Fast stage: `--profile fast --release`, fail-fast; unmutated fast baseline was 168 passed / 14 skipped, 0 failures, so nothing had to be excluded. Fixtures: `EC_REQUIRE_FIXTURES=1` everywhere; baselines passed with the test started.

Validity checks: baseline logs show `PASS` for exactly the one test; SURVIVED rows have `rc=0 ran=1`; KILLED rows have `rc=100`. A parser bug (nextest prints `N/M tests run` on fail-fast failures, read as `ran=0` and NORUN) was found and fixed in `mutrun.py`; the fast stage was rerun after the fix. Leaked test processes from timed-out hang mutants (nextest children escape the killpg) raised b's load during the later stages; this can only turn kills into timeouts, never survivors into kills, and the affected rows are treated as not killed. They were killed by PID afterwards.
