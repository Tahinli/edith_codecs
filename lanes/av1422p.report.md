## Outcome

1. Step 1 of the charter (print before adding): with the header refusal
   temporarily bypassed (probe-only, restored byte-identical), the stop
   printed `EC_422P_STOP decode_block_rect4 chroma shape (4,32) luma=(8,32)
   ss=(1,0)` — the portrait 1:4 leaf the av1422o report named as its
   frontier, on the pinned fixture (sha256 `d3fa4beeb1309033e4a03f5ae5c4
   31c8fa8386ba1ada088684710423c7938129`).
2. Measured, not guessed: `av1_get_tx_size` reads
   `max_txsize_rect_lookup[plane_bsize]` with plane_bsize =
   `ss_size_lookup[BLOCK_8X32][1][0]` = BLOCK_INVALID (255, `enums.h`). The
   byte at +255 of the copy `decode_token_recon_block` actually reads
   (objdump: every `movzbl 0xc0d030(%r*)` in that function) is `0x05` =
   TX_4X8; `av1_get_adjusted_tx_size` has no TX_4X8 case. The decodetxb copy
   of `num_pels_log2_lookup` (the `cmpb` against `0xc0db70(%r15)`, symbol at
   0xc0de70) reads `0xff` at +255, so `get_txb_ctx_general`'s chroma branch
   (`txb_common.h`: `num_pels_log2_lookup[255] > num_pels_log2_lookup
   [BLOCK_4X8]`) takes the offset-10 arm. Both bytes re-measured on the
   pinned Release oracle this session.
3. The chunk (libaom `decode_token_recon_block` semantics: stepr =
   `tx_size_high_unit[TX_4X8]` = 2 4-px rows, stepc = 1, unit_width/height
   ROUND_POWER_OF_TWO down to (1, 4)): FOUR stacked TX_4X8 units per plane
   (chroma rows 0, 8, 16, 24), plane-major, riding the existing
   `(4, 8) => ChromaRect8x4` entropy class via [`read_rect_chroma_unit`] —
   no coefficient-table row added (BLOCK_4X32 is not a table libaom has).
   Each unit is read and recorded immediately: unit row 0's txb_skip_ctx
   sees the real neighbour states, lower units see the block's own upper
   unit's, and each unit predicts off the upper one's samples. The skip arm
   walks the same units (`predict_and_reconstruct_intra_block` predicts
   every unit regardless of `skip_txfm`). CfL parameters are computed once
   per block over the strip's 8x32 luma and shared by all units. Luma is
   the same single TX_8X32 rect the general arm reads.
4. The chunk units' `txb_skip_ctx` is `above + left + 10`
   (`get_txb_ctx_general`): the port's offset-7-first `txb_skip_chroma_8`
   stores the offset-10 rows at rows 3..6 (lane-av1-422b), so
   [`read_rect_chroma_unit`] gained a `chroma_skip_offset: Option<usize>`
   parameter (mirroring [`read_plane`]'s `chroma_ctx_offset`) and this arm
   passes `Some(3)`. Every existing caller passes `None` =
   behavior-identical (their rect unit IS the whole plane block, offset-7
   rows); the whole-rect read never sees the new `(4, 32)` match row.
5. 4:2:0 and 4:4:4 are on their existing paths: the chunk is gated on
   `(chroma_w, chroma_h) == (4, 32)` at ss(1,0), which only an 8x32 luma
   strip at 4:2:2 produces (4:2:0 reads (4, 16), 4:4:4 reads (8, 32)); the
   stale "portrait leaves are unreachable / a conformant stream cannot
   carry that leaf size" comment is disproven by the fixture and replaced.
