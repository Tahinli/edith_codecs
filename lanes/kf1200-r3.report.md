# lane-kf1200 r3 report — the partial-bottom-row desync, root cause found and fixed

Tip `9d18288` on `lane-kf1200` (parent `bee8ec0`, main merged at `d85d7d2`).

## Root cause (ONE symbol, not the partition path the charter suspected)

The charter's premise — "our 32-level gathered `split_or_horz` CDF/ctx differs" —
is REFUTED by measurement. A cross-decoder range ladder over the whole partial
bottom superblock row shows every partition symbol of mi_row=400 in sync,
including the gathered ones (our `ctx` values equal libaom's
`partition_plane_context` minus its `bsl * PARTITION_PLOFFSET` offset, and every
`rng` matches):

    aomdec  EC_PART mi_row=400 mi_col=44 bsize=6  ctx=6 rng=55482   value=3 (SPLIT)
    ours    OUR_PART mi_row=400 mi_col=44 bsize=6 ctx=2 rng=55482
    aomdec  EC_PART mi_row=400 mi_col=44 bsize=3  ctx=0 rng=52288
    ours    TRACE partition_w8 mi=(400,44) ctx=0 value=0 pre_rng=52288
    aomdec  EC_PART mi_row=400 mi_col=46 bsize=3  ctx=0 rng=53128
    ours    TRACE partition_w8 mi=(400,46) ctx=0 value=0 pre_rng=53128

The first differing element is the `tx_depth` symbol of the SECOND 8x8 leaf:

    aomdec  EC_ISTEP mi_row=400 mi_col=46 name=tx_depth val=0 ctx=1 rng=42998
    ours    EC_ISTEP mi_row=400 mi_col=46 name=tx_depth val=0 ctx=2 rng=54191

Same decoded value, different CDF row, therefore a different interval narrowing:
the entropy stream is desynced from there on, and the rest of the row (and the
1595..1607 deblock spill) decodes as garbage. What the charter saw as "aomdec
reads a 16x8 where we read 32x16" was our *already desynced* reader at
mi (400,48), one block later.

`ctx` comes from libaom `get_tx_size_context`: `above_txfm_context[0] >=
max_tx_wide` + `left_txfm_context[0] >= max_tx_high`. The left neighbour of
(400,46) is the 8x8 leaf at (400,44), which is `skip=1` and whose `tx_depth`
resolved to TX_4X4 — so libaom's `set_txfm_ctxs` published 4 and its left term
is 0. Our `decode_leaf8` skip branch fell through to a hardcoded
`fill_lf_grid(leaf_mi, 2, 8, 0)`, publishing 8, so our left term read 1.

An intra block reads `tx_depth` whether or not it is skipped (libaom
`read_intra_frame_mode_info` calls `read_tx_size` above the skip branch); only a
skipped *inter* block records its block size instead of its transform.

  (was the literal `8`). The non-skip TX_4X4 branch already returned early with 4;
  only the skip path was wrong. One line.
- `crates/ec-av1/src/decode.rs:2652` `trace_edge()` + 5 call sites — `OUR_PART
  mi_row/mi_col/bsize/ctx/rng` under `EC_AV1_TRACE` for the three gathered
  frame-edge partition reads (there was no emitter for them, only for the full
  alphabet reads), plus `pre_rng` on the 8x8 partition trace. Instrument only.
- `crates/ec-av1/examples/decode_probe.rs:34` — prints `skip_split_tx`.

Sibling sweep for the same shape (a skip branch publishing the block side where
the resolved transform belongs): `fill_lf_grid` has 6 call sites.
`decode_block` (9872) already passes `logical_tx`; the inter 8x8 leaf (20449)
passes `if split8 {4} else {8}`; the inter-leaf skip early-return (19644) passes
8, which is CORRECT — a skipped inter block records its block size. The 4x4 leaf
(10541) passes 4. Only 10330 was wrong.
