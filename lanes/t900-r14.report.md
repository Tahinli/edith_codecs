# lane-t900 r14 report -- the last 1080p residue class: OBMC neighbour prediction size

Branch `lane-t900`, base `a870796b` (main, merged fast-forward at round start).

## Root cause (one, all of TARGET A)

`overlappable_above` / `overlappable_left` (`crates/ec-av1/src/decode.rs`) clamped the
neighbour span to `end_col`/`end_row`, i.e. to `mi_cols`/`mi_rows`. libaom's
`foreach_overlappable_nb_above`/`_left` (`av1/common/obmc.h:52,83`) pass
`op_mi_size = AOMMIN(xd->width|height, mi_step)` -- the block's OWN side, never the
frame-edge clamp; `end_col`/`end_row` bound only the WALK. `build_obmc_inter_pred_*`
(`reconinter.c:891`) then predicts a strip `op_mi_size * MI_SIZE >> ss` tall/wide, and
the destination write runs off into the frame buffer's own padding.

Because our span shrank at the frame edge, the neighbour PREDICTION shrank with it, and
at 4 chroma rows `mc::predict_with_filters` picks the 4-tap narrow vertical kernel
(`mc.rs:418`, class `narrow-block-sharp-kernel`) where libaom used the 8-tap one.
Result: a 1-off on the last valid chroma row of the OBMC blend -- 1-13 B on 36 of 267
frames of the 900 s 1080p cut and similar counts on every other 1080p cut.

Fix (`a6c408b7`): span is `step.min(bw4)` / `step.min(bh4)`; the prediction is built at
that full size (kernel choice included) and only the WRITE into this block's own
prediction buffer is clipped (`obmc_blend_v` gained the tmp stride, `obmc_blend_h`
takes the clipped row count).

Witness (`52a11095`): `obmc_edge_span_hits` counts neighbour strips running past
`mi_rows`/`mi_cols`; the 128-SB inter witness gate hard-asserts it (fires 33x).
