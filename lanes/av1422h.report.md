# lane-av1-422h — 4:2:2 sub-8/rect chroma model proven rng-exact to the bottom-edge SBs; refusal stays

## Outcome

The assignment's premise — "ours reads a non-SPLIT partition at mi(8,10)" — was
FALSE, and this round proves it with partition-level oracle traces: at mi(8,10)
both decoders read `bsize=3 ctx=0 rng=37068 → value=1` (PARTITION_HORZ).
`read_partition` in the oracle source already carried an `EC_PART` probe
(patch never enabled by the 422f/g generation recipe), so this round's traces
are the first with the walk checkpointed per partition read; pairing them
(`EC_PART` rng values, tell offset constant +14) shows the true first
divergences and lets every fix below be verified rng-for-rng.

Four 4:2:2 chroma-model defects found and fixed (all in `decode_leaf_rect8`,
`decode_leaf8`, `decode_leaf_split4`/`sub8_leaf_chroma422`, `decode_block`):

1. **`decode_leaf_rect8` (BLOCK_8X4/BLOCK_4X8 strips) used the 4:2:0
   `i == 1`-only chroma rule.** `is_chroma_reference`
   (av1_common_int.h:1459) at ss (1,0): a HORZ pair's BLOCK_8X4 strips are
   BOTH chroma references (`!(bw & 1)`), a VERT pair's BLOCK_4X8 strips keep
   the odd-column leaf. Oracle evidence at the mi(8,10) HORZ pair: uv_mode
   read at BOTH (8,10) and (9,10), each strip followed by its own one-TX_4X4
   chroma unit per plane. Fixed `has_chroma` to `!vert || i == 1` at 4:2:2
   and decoded each reference strip's chroma right after its luma via
   `sub8_leaf_chroma422` (split path, whole-leaf path, intrabc path), with
   the 4:2:0 group tail gated off at 4:2:2 and the coarse uv slots filled
   from the last reference strip. The mi(8,10) pair now decodes
   rng-for-rng (strip mode reads end at oracle's exact rngs 63250/33264).
2. **`decode_leaf_split4`'s 4:2:2 column parity was inverted** (422g's
   `(mi_col & 1) == 0` "even-column" rule — derived by 422f from a
   pre-partition-trace misreading of the (8,10) HORZ pair as a split
   group). Oracle, mi(30,42) split group: uv_mode read at mi(30,43) and
   mi(31,43) ONLY — the ODD columns, per the formula's column clause
   `(mi_col & 1)`. Fixed to `(lmi.1 & 1) == 1`.
3. **`sub8_leaf_chroma422` anchored the odd-column leaf's ctx read/write at
   the leaf's own column.** libaom anchors at the FLOOR chroma cell
   (`pd->above_entropy_context + blk_col` with `blk_col = mi_col >> ss_x`):
   an odd-column 4x4 leaf's unit starts at chroma px 86, whose containing
   cell is luma mi col 42, so the ctx read AND the per-TU state write land
   on luma mi 42,43, not 43,44. Added `ctx_mi = (lmi.0, lmi.1 & !1)`.
4. **`decode_leaf8`'s 4:2:2 chroma rect unit read its txb ctx through the
   plain `around_mi`** — the 422f-class dc-vote double-count (one chroma
   ctx cell spans TWO luma mi columns at ss_x 1) in the leaf8 path.
   Oracle evidence at mi(2,24) plane 2: ours dc_sign row 0, oracle row 2.
   Both 422 arms now read `around_mi_422_chroma(leaf_mi, 8, 8)`.
