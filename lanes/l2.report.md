The task text priced the lever from `last2_census`'s doc comment, which still
claimed `ref_frame_idx` aliases `LAST2` onto `LAST`'s slot and called the
build "a week of wall". That premise was STALE at the base: lane-last2

## 5. Procedure notes (for the next lane on VPS-1)

- A sequential multi-gate chain script on the VPS (one systemd-run unit per
  gate, `--wait`, per-gate log files, LOADAVG before/after each unit echoed
  into one chain log) keeps "one gate at a time" honest across a ~3 h batch
  without a babysitting ssh session; the four gates cost 52m/54m/35m/36m.
- A control row may legitimately differ from the standing table where a
  MERGED default changed it — diff the delta against the merge message's own
  recorded number (here intertx's "+14.4 -> +13.7") before declaring
  substrate suspicion. Reproduce-to-the-digit everywhere else is what makes
  the one moving row attributable.
- `--ignored --exact` needs the full test path even for the diagnostic
  censuses (`encode::tests::last2_census`, not `last2_census`).
