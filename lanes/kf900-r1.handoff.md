## ROOT CAUSE (fixed)

`crates/ec-av1/src/decode.rs`, `decode_leaf8` tail — was:

```rust
neighbours.fill_lf_grid(leaf_mi, 2, 8, 0);   // literal block side
```

now `neighbours.fill_lf_grid(leaf_mi, 2, resolved as u8, 0);`

libaom calls `set_txfm_ctxs(mbmi->tx_size, bw, bh, skip_txfm && is_inter_block(mbmi), xd)`
(`decodemv.c`). For an INTRA block that skip term is **always 0**, so a *skipped* 8x8 intra
leaf whose `tx_depth` symbol resolved to `TX_4X4` still publishes **4** to the next block's
`get_tx_size_context` (`pred_common.h:342`). Our tail wrote **8** for every 8x8 leaf,
including the skipped-and-split ones (`decode_leaf8`'s non-skip `resolved == 4` branch had
its own early return with the correct 4 — only the skip path fell through to the literal).

Consequence: the 8x16 strip below such a leaf computed `tx_size_context_rect` = 2 where
libaom computes 1, and read `tx_size_cat1` **row 2** instead of row 1 — same 3-symbol
alphabet, wrong CDF row (class `wrong-alphabet-same-value`). The msac range diverged
mid-frame, **no refusal**, everything after it garbage.
