## (b) Shape change — why `#[ignore]`, and what it stops

`crates/ec-h264/tests/conformance.rs:1846` `real_library_streams_match_ffmpeg`.

The precondition is a personal media library, which has exactly two possible
behaviours on a runner, and **both are wrong**:

- manifest absent → the existing `SKIP: … missing` early return prints
  **green**. That is the silent-skip class this batch is removing: a green that
  means "nothing was checked".
- manifest present but its absolute paths unresolvable (a host that ran the scan
  script against an empty library) → zero files swept and `decoded >= 3` fails.
  That is **the red every fleet run currently eats**, and it is red for a reason
  that has nothing to do with the decoder.

`#[ignore]` over an env-gated SKIP, justified: an env gate whose variable is
absent on the runner prints *the same green the missing manifest already prints* —
that is the defect, not the fix. An ignore is visible in
`cargo test -- --list`, cannot go green silently, and needs no runner-side
configuration that could itself drift. The assertion is untouched: `decoded >= 3`
still stands, and still holds, on the machine that can run it (it did: 15 ≥ 3).

Verified — the target is no longer red, and the reason is printed verbatim:

```
test real_library_streams_match_ffmpeg ... ignored, sweeps the PERSONAL media
library (~/Videos, ~/Downloads, ~/Music) through the gitignored
fixtures/real-library-manifest.tsv; MINUTES of wall time (measured past 840 s on
the workstation), so workstation only -- budget an hour, it is not wedged. ...
test result: ok. 0 passed; 0 failed; 1 ignored; 0 measured; 22 filtered out
```

Also fixed, because the fix is the *identical* one-line `#[ignore]` + reason and
no judgement call: `crates/ec-aac/tests/oracle.rs:680`
`real_library_tracks_match_ffmpeg` — same manifest, same
"skip if manifest missing, then assert `checked >= 3`" shape, same two failure
modes. Verified reporting `1 ignored`.
