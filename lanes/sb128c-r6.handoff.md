# lane-sb128c r6 -> r7 handoff: the 128-root HORZ/VERT/AB partition work

Worktree `edith_codecs-sb128c`, `CARGO_TARGET_DIR=$HOME/.cache/cargo-target-sb128c`.
r6 merged main 727f29a + lane-golomb 173b793 and re-greened the five 128 gate arms;
it did NOT start the partition work. Everything below is measured this round.

## The blocker on the 1080p AV1 film is ONE arm: the GATHERED bottom-edge HORZ

`decode_probe` on four extracts of the 1080p 10-bit AV1 film (2 s each, `-c:v copy`)
all stop at `a 128x128 superblock HORZ/VERT or AB partition`, and
`EC_AV1_TRACE=1 | grep partition_w128` shows values **0 and 3 only** right up to the
stop -- i.e. the refusing partition never came from the full-alphabet symbol (which
traces every value) but from `read_sb128_root`'s GATHERED branch (`decode.rs:13317`,
no trace line): frame height 1080 gives `mi_rows = 270`, so the bottom 128 row has
`mi_r128 = 256`, `256 + SB_MI(16) = 272 > 270` -> `has_rows128 == false`, one gathered
bit, and the film codes it as `PARTITION_HORZ` (a 128x64 block whose bottom 8 luma rows
are the only ones in frame). Frame width 1920 = 15*128 exactly, so `has_cols128` is
always true and the VERT gathered arm is unreachable on this film.
=> r7's minimum for the film is the **128x64 block** (key + inter), not the whole set.

## Shape of the 128x64 / 64x128 block (spec + libaom, for r7)

- luma: `max_txsize_rect_lookup[BLOCK_128X64] = TX_64X64` -> two TX_64X64 units, each
  coding only its top-left 32x32 (`default_scan(tx_px.min(32))`, already the convention
  at decode.rs:17540/:18670).
- chroma: `av1_get_max_uv_txsize(BLOCK_128X64) = TX_32X32` over a 64x32 uv block -> two
  units per plane, uv block > uv tx, so the txb_skip CDF takes the offset-10 rows.
- coding order: two 64x64 mu chunks (`decode_token_recon_block`), Y then U then V per
  chunk -- the existing `side > 64` chunk loop in `decode_inter_block` (decode.rs:17568)
  already does this for four chunks; it keys the chunk on `(row/16, col/16)`.
- `motion_mode`/`obmc` rows BLOCK_64X128 (14) / BLOCK_128X64 (15) are already in
  `cdf.rs` (added r5, packed indices 14/15/16 with 128X128).
- `has_top_right`: `mvstack::has_top_right` returns 0 for `bs0 = max(bw4,bh4) > 16`, so
  both 128x64 and 64x128 have no top-right candidate; the probe is now gated
  (mvstack.rs:882/:1680), nothing more to do there.
- lf grid: per-unit write with the skip-inter suppression, luma-only leaf write
  (`fill_lf_grid_leaf_luma`, from lane-golomb) -- both already merged in r6.
- one `cdef_idx` literal per block, copied to every 64x64 CDEF unit the block covers
  (the pattern at decode.rs:13606 / :21744).
- palette (>64), CfL (>32) and filter intra are all size-refused already.
- AB visit order (libaom `decode_partition`): VERT_A = 64x64 TL, 64x64 BL, 64x128 right;
  VERT_B = 64x128 left, 64x64 TR, 64x64 BR; HORZ_A = 64x64 TL, 64x64 TR, 128x64 bottom;
  HORZ_B = 128x64 top, 64x64 BL, 64x64 BR.
