# lane-sb128c r10 report

Tip `1f6d885` on `lane-sb128c` (from `c24a2ac`). The r9 blocker is closed: two
root causes, both in code shared by every block wider or taller than 64.

## Root cause 1 -- `tx_size_context_rect` compared against the block side

`crates/ec-av1/src/decode.rs:5845` `tx_size_context_rect` tested the above/left
neighbour transform sizes against the block's own `bw`/`bh`. libaom's
`get_tx_size_context` tests against `max_txsize_rect_lookup[bsize]`, which tops
out at TX_64X64: a 64x128 block must compare against 64, not 128. The square
path (`read_tx_depth`, decode.rs:11838) already capped with `side.min(64)`
(lane-sb128b r1); the rect path never did. Consequence: the right 64x128 half
of a 128-root PARTITION_VERT at mi_col 80 read its tx-depth symbol off CDF row
0 where libaom uses row 1, decoded depth 0 (TX_64X64) instead of depth 2
(TX_16X16), and the tile desynced from that block on.

Fix: cap both dimensions at 64 inside the helper (one `min`), so all eight call
sites are covered at once.

## Root cause 2 -- `Reach::of_tu` ignored the 64x64 "mu" chunk order

`crates/ec-av1/src/encode.rs:1252` `Reach::of_tu` used the plain
`col_off + tx_w < bw` rule. A block wider than 64 is coded in 64x64 chunks in
raster order, so `has_top_right` (reconintra.c) takes `col_off` MODULO the
64-wide chunk in its `row_off > 0` branch (with one exception: the unit whose
top-right corner is the centre of a 128x128), and `has_bottom_left` grants the
left edge of a right-hand chunk what the already-coded left chunk holds.
Without it the last unit column of every chunk of a 128x64 intra block
predicted from a chunk libaom has not decoded yet -- 375 wrong luma samples in
the first such block of a 512x512 key frame, entropy exact.
