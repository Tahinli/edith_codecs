libaom `av1/common/av1_loopfilter.c`, `set_one_param_for_line_luma` (~line 690)

```c
const int32_t pu_edge = mi_prev != mbmi;
```

`get_transform_size` still reports TX_64X64 (luma) / TX_32X32 (chroma) for a

block in the gate stream is `is_inter=1 skip=1`.

GRID WRITE (`crates/ec-av1/src/decode.rs`), final shape:
- the per-leaf `fill_lf_grid_rect` loop in `decode_inter_block` is gated on

- new `Neighbours::suppress_internal_lf_edges(at_mi, w_mi, h_mi)` writes the
  UNCAPPED chroma extent (64 for a 128 block) into `uv_tx_grid`/`uv_tx_h_grid`,

- `dump_stage` now indexes its file per decode-order picture
  (`EC_AV1_POSTDEBLOCK_DUMP` overwrote `.f0` every frame, so only the last
  picture was comparable against aomdec's indexed rung). This is the instrument

## (1b) THE UV-CAP TRAP (cost one suite run; do not repeat)

My first fix instead removed the `.min(32)` TX_32X32 cap inside
`fill_lf_grid_rect` outright, reasoning it was inert for every block up to 64
wide. It is inert only for the INTER path. libaom's `curr_skipped` term
contains `is_inter_block(mbmi)`, so an INTRA 128x128 block's internal chroma TU
edges (every 32 chroma px, `av1_get_max_uv_txsize(BLOCK_128X128) == TX_32X32`)
ARE filtered. Removing the cap broke the sibling gate
`a_real_aomenc_key_frame_with_a_128x128_none_partition_decodes_pixel_exact`
(caught mid-suite at 293/404). The cap is restored; suppression is now explicit
and inter-only. Both gates re-run together after the correction:
`key_frame_with_a_128x128_none_partition ... ok`, inter gate now fails one
frame LATER (see below). Class: `fix-trades-sibling-gate`.

## (1c) cdef_idx per 64x64 quadrant -- the r4 charter's suspicion is WRONG

`read_cdef` (`av1/decoder/decodemv.c`) reads at most ONE literal per CALL and is
called once per BLOCK. A `PARTITION_NONE` 128 root is one block, so exactly ONE
`cdef_idx` symbol is read (`index = cdef_unit_col_in_sb + 2*cdef_unit_row_in_sb`
= 0 at the SB origin) and stored in the block's own `MB_MODE_INFO`, which all
four 64x64 CDEF units point at. r1's "replicated over 4 quadrants" is CORRECT;
no change was made. Four symbols are read only when the root SPLITs into four
non-skip 64s -- and for a 128-level HORZ/VERT root there are TWO blocks, hence
up to TWO literals: re-derive the index from that function, do not assume.
