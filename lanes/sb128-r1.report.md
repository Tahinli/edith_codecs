## What changed

- `crates/ec-av1/src/decode.rs`
  - `SB128` thread-local + `set_sb128` (also sets `Reach`'s superblock size), `sb_mi_cur()`.
  - `sb_visit_order()`: at sb128 the tile walks each 128x128 superblock's four 64x64
    quadrants (TL, TR, BL, BR) before the next superblock — libaom `decode_partition`'s
    recursion order, not raster over 64x64 superblocks.
  - key-frame tile loop: per 128 superblock, one `read_lr` over the whole 128x128 and one
    `partition_w128` symbol (8-symbol alphabet, no HORZ_4/VERT_4 at BLOCK_128X128; forced-split
    gather `gather_of` + `VERT_ALIKE128`/`HORZ_ALIKE128` at the frame edge). SPLIT recurses
    into the existing 64 path; the other seven arms refuse by name.
  - `maybe_read_delta_q` / `maybe_read_delta_lf` key off `sb_mi_cur()` (once per 128x128, not
    four times), and `is_whole_sb` is ignored at sb128 (no leaf can be a whole 128 superblock).
  - `NO_NEIGHBOUR_SIDE = 128` replaces `SB` as the partition-context sentinel — ROOT CAUSE 1.
  - intrabc under sb128 refuses by name (`av1_is_dv_valid`'s delay is sb_size-derived).
- `crates/ec-av1/src/encode.rs`: `Reach`'s `has_top_right`/`has_bottom_left` masked the block
  position with a hardcoded 64 superblock; now `reach_sb_px()` (64 or 128) — ROOT CAUSE 2.
  The tables themselves were already 128-relative (`table_stride`), only the masks were wrong.
- `crates/ec-av1/src/cdf.rs` / `cdf_state.rs`: `PARTITION_W128` (entropymode.c:154's four
  `AOM_CDF8` rows), stored, reset per frame like `partition_w64`.
- `crates/ec-av1/src/stream.rs`: `set_sb128` per frame, scoped inter refusal, two gates.
- `crates/ec-av1/src/refusal_inventory.rs`: the three new refusals listed.

Two defects found and fixed, both invisible at 64:
1. the no-neighbour partition-context sentinel (64) set the ctx bit at the 128 root — our ctx
   was 3 where aomdec printed `ctx=16` (= `bsl*4 + 0`, row 0). Identical at every level <= 64,
   so no existing gate could see it.
2. `has_top_right`/`has_bottom_left` answered against a 64 superblock — a bounded 1391-luma-pixel
   band (x 124..255, y 44..67) with the entropy stream still in sync.

## Refused by name (still), each with its string

- `a 128x128 superblock partition other than SPLIT (NONE/HORZ/VERT and the four AB arms at the
  128 root are not decoded)` — the six 128-level non-SPLIT arms + a 128x128 leaf. The gate pins
  `--max-partition-size=64` so the encoder never chooses them. deferred: 128-level NONE/HORZ/VERT
  (a 128x128 block is 2x2 TX_64X64 luma + 2x2 TX_32X32 chroma; `decode_block` codes ONE luma TU
  per block outside the `tx_select` multi-TU branch and one chroma TU always) — unblocked by a
  multi-TU chroma path in `decode_block`.
- `an inter frame under a 128x128 superblock (this decoder's inter tile path recurses a 64x64
  superblock root only)` — scoped to frames > 64x64 (a <=64x64 frame's 128 root reads no symbol).
  deferred: inter at 128 — the second `for sb_r/sb_c` loop in `decode.rs` (~line 17800) plus OBMC
  and mvstack neighbour caps — unblocked by porting `sb_visit_order` + the 128 prologue there.
- `intrabc under a 128x128 superblock (...)` — accepted for this round.
