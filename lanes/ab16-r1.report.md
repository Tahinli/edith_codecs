# lane-ab16 r1 — the four AB partitions at 16x16, arm by arm

Branch `lane-ab16`, off `lane-rectx` `fad4d5a`.

## What changed

- `crates/ec-av1/src/decode.rs` ~7140: the 16x16-level `PARTITION_HORZ_A/_B/VERT_A/_B` arms
  (replacing the old VERT_B-only arm and the "codes only the square arms" refusal). libaom
  `decode_partition` visit order: HORZ_A = TL 8x8, TR 8x8, bottom 16x8; HORZ_B = top 16x8,
  BL, BR; VERT_A = TL, BL, right 8x16; VERT_B = left 8x16, TR, BR. Squares go through
  `decode_leaf8`, strips through `decode_leaf_rect` (lane-rectx's real non-skip 16x8/8x16
  coefficient path — the old VERT_B arm used `decode_block_rect`, which refuses non-skip at
  this size). `write_back_split_modes` for the coarse slot; mi-granular records come from the
  two leaf writers. VERT_A/_B take `Reach::vert_ab_partition()` (TL,BL,TR,BR visit order).
- `crates/ec-av1/src/decode.rs` ~7395: the surviving refusal is narrowed to the 1:4 case,
  `"a 1:4 partition below 16x16 (PARTITION_HORZ_4/VERT_4 ...)"`. The arm test is
  `(PARTITION_HORZ_A..=PARTITION_VERT_B).contains(&part16)` — values 8/9 must NOT fall into it.
- `crates/ec-av1/src/decode.rs` ~3401: `decode_block_rect`'s `"a coded (non-skip)
  HORZ_B/VERT_B rect strip below 16x16"` branch deleted — every remaining call site passes
  32x16 or 16x32, so it was dead once VERT_B moved to `decode_leaf_rect`.
- `crates/ec-av1/src/decode.rs` ~430: `AB16_HITS: [usize; 4]` + `ab16_hits_by_arm()`.
- **Coordinator-reported base defects, fixed here too** (same hunks are being made on
  lane-sub8 r6 / lane-rectx r5 — semantically identical, keep either at merge):
  - `mode_above_mi`/`mode_left_mi` guard with `> self.tile_row0_mi` / `> self.tile_col0_mi`
    instead of `> 0`, and the mi-exact mode maps are reset in `start_tile` (col span) and
    `start_row` (`decode.rs` ~2037/~2304/~2581).
  - `encode.rs` `top_right_rect`/`bottom_left_rect` index with `blk_row << (5 - bw_log2)`
    (libaom `MAX_MIB_SIZE_LOG2`), not 4.
- `crates/ec-av1/src/encode.rs`: lane-part32 `fd1a2eb`'s encode half cherry-picked
  (`HAS_TOP_RIGHT_VERT`/`HAS_BOTTOM_LEFT_VERT`, `VERT_AB_PARTITION`, `VertAbGuard`,
  `Reach::vert_ab_partition()`). Their decode.rs/stream.rs halves were NOT taken (they depend
  on part32's own 32-level AB arms and counters) — a merge of both branches touches the same
  two `top_right`/`bottom_left` table-pick hunks.
- `crates/ec-av1/src/stream.rs` ~5460: the gate. `crates/ec-av1/src/refusal_inventory.rs`:
  one refusal deleted, one narrowed. `gate_coverage.rs` needed no edit (`--enable-ab-partitions`
  is now positively exercised and was never on a NEVER_EXERCISED list; this base has no
  `NEVER_EXERCISED_10BIT` list — that is on main `79d4f16`, so the merge must delete the AB
  entry there if present).
