# lane-av1-422d — 8x8 leaf chroma unit ported at ss (1,0); refusal stays

## Outcome

STOP with the 4:2:2 header refusal in place. `decode_leaf8`'s chroma walk now
ports the 4:2:2 leaf unit (ONE 4x8 rect transform unit per plane,
`TxbSet::ChromaRect8x4` + `SCAN_4X8`, one txb_skip + one scan), and every leaf8
chroma read on the measured fixture is rng-for-rng EXACT against the oracle.
The stream still desyncs LATER, at `decode_leaf_rect`'s chroma arm (next
section), so the refusal is retained byte-identical and the probe bypass was
reverted before commit.

## Change (all inside decode_leaf8's own chroma scope)

- `decode_leaf8` (decode.rs): `chroma_422 = ss_x == 1 && ss_y == 0`; all three
  arms (skip, single-8x8-unit, TX4) branch to `leaf8_chroma422_unit` for the
  rect unit. The 4:2:0 `(4, TxbSet::Chroma4, scans.1)` selection and the 4:4:4
  arm are untouched. The chroma unit does NOT follow the luma var-tx split
  (`uv_txsize` is `av1_get_max_uv_txsize` of the block, still one 4x8 unit
  when luma resolves TX_4X4). The intrabc DV copy covers the whole plane block
  (4x8) at ss (1,0).
- `leaf8_chroma422_unit` (new, next to `decode_leaf8`): mirrors
  `sub8_leaf_chroma444`'s rect arm at the leaf's halved position — entropy
  context from the leaf's own 8x8 luma-span above/left state (no `+3`, the
  unit covers the plane block exactly), CFL source the leaf's whole 8x8 luma
  block, mode-derived default `tx_type` unless `INTRABC_CHROMA_TX` is armed,
  prediction override (intrabc DV over palette) set inside, skip predicts with
  `ZERO_RESIDUAL`.
- UV palette map extent (decode.rs:15808, leaf8's mode-info reader): the map
  is decoded over `(side >> ss_x, side >> ss_y)` = 4x8 via
  `decode_color_index_map_wh`, not the square call's `(side >> ss_x)`-squared
  4x4 (class: plane-block extent squared a rect). At 4:2:0/4:4:4 the arguments
  evaluate identically; only ss (1,0) changes. Found live: the 16-entry map
  fed a 16-sample prediction override into the first 32-sample rect unit and
  panicked `reconstruct_rect` (`index out of bounds: the len is 16 but the
  index is 16`).

## First remaining divergence (named next site)

`decode_leaf_rect`'s chroma arm, decode.rs:13060-13067. For a 16x8/8x16 rect
leaf at ss (1,0) the chroma plane block is 8x8 — SQUARE
(`TxbSet::Chroma8` + `default_scan(8)` through `read_plane`, the
`chroma_tiled` (8,8) shape) — but the code picks `TxbSet::ChromaRect8x4` +
`SCAN_8X4`/`SCAN_4X8` keyed on `ss_x == 0`. Measured: the HORZ_A's 16x8 strip
(mi_row=2, mi_col=0) — oracle U/V units are `tx_size=1` (TX_8X8 class, 64-
position eob alphabet, ctx=8); ours enters the U unit's txb_skip at the same
rng 38672 and coincidentally matches that one symbol (the offset-7 row shares
`txb_skip_chroma_8`), then reads eob off the 32-position chroma-rect alphabet
(eob=27 vs oracle eob=32) and desyncs. Everything after shifts.
