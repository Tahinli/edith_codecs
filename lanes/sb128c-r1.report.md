## What changed

- `decode.rs` `read_sb128_root` call site in the inter tile loop (~20826): `PARTITION_NONE` now sets
  `sb128_none` and decodes one 128x128 block through the existing `inter_piece!` macro
  (`TxbSet::Luma64/Luma64/Chroma32`, `TX32`, `scan32`, size group 3 — `size_group_lookup[BLOCK_128X128] == 3`),
  then replicates the block's `cdef_idx` across its four 64x64 units and skips the superblock's other three
  quadrant items (same skip the key-frame loop runs).
- `decode.rs` `inter_txbset_for`: `64 => TxbSet::Luma64` — `av1_get_ext_tx_set_type` is `DCT_ONLY` at
  `tx_size_sqr_up == TX_64X64`, so no `tx_type` symbol is coded and the intra/inter sets coincide.
- `decode.rs` `read_block_tx_size`: with `tx_mode == TX_MODE_LARGEST` a 128x128 inter block is still FOUR
  TX_64X64 units (`max_txsize_rect_lookup[BLOCK_128X128]`), returned as leaves; the var-tx leaf refusal
  moves from `> 32` to `> 64`.
- `decode.rs` `decode_inter_block` (both identical coefficient regions, compound and single-ref): the leaf
  loop's scan is `default_scan(tx_px.min(32))` (a 64-point transform codes only its 32x32 corner), and at
  `side > 64` each 64x64 mu chunk's U and V units are read INSIDE the leaf loop right after that chunk's
  luma leaves (libaom `decode_token_recon_block` codes every plane of a chunk before the next chunk —
  sb128b r3 measured this against aomdec), recorded per unit, and collected for the block-level write-back.
- `decode.rs` `read_inter_plane`: on a chroma plane the `luma_skip_ctx` parameter now carries
  `get_txb_ctx`'s offset (+3 selects `txb_skip_chroma_32`'s offset-10 rows, the uv-plane-block-larger-than-
  the-transform case). All existing chroma callers pass `None` — inert.
- `decode.rs` OBMC: `overlap_above/left` capped at `min(write_h|write_w, 64) / 2`, libaom
  `reconinter.c:860` / `:899` (`AOMMIN(block_size_high[bsize], block_size_high[BLOCK_64X64]) >> 1`).
  Without it a 128 block asked `obmc_mask(64)`, which panicked `unreachable!` — the first thing Troy hit.
- `stream.rs`: new gate `a_real_aomenc_inter_128x128_none_root_decodes_pixel_exact` (currently `#[ignore]`d,
  see below). `refusal_inventory.rs`: one line replaced.

## The gate, and why it is RED

`a_real_aomenc_inter_128x128_none_root_decodes_pixel_exact` — real aomenc `--sb-size=128 --cpu-used=0
--max-partition-size=128 --min-partition-size=32 --cq-level=62 --limit=8`, 256x256 (both dims > 128, so
NONE/HORZ/VERT at 128 are real choices), 3 arms (8-bit tx-size-search=0, 10-bit tx-size-search=0, 8-bit
tx-size-search=1), sequence-header assert on `use_128x128_superblock` + bit depth, hard
`inter_sb128_none_hits >= 1` per arm, every decode-order frame through `decode_all_frames_vs_oracle`
(panics on refusal or any differing byte, so out-of-scope mismatches are structurally 0), flags spelled once.

It FAILS on arm 1: `sb128c-inter-none-8-false: this decoder refused the stream: unsupported: AV1 tile
(a split intra strip whose transform unit is 32x64 ...)`.

Triage done this round:
- The recipe genuinely fires the shape: `EC_AV1_TRACE=1 decode_probe g8.obu` shows
  `partition_w128 value=0` (PARTITION_NONE) **4 times** and `value=3` (SPLIT) 10 times.
- The KEY frame alone (`--limit=1`, `k1.obu`) decodes: `OK: 1 frames decoded, 256x256`.
- The stream is encoded with `--enable-rect-partitions=0`, so a 64x128/32x64 intra strip cannot be in it:
  the 32x64 refusal is OUR desync talking (class `refusal-from-own-desync`) somewhere at or after the first
  inter 128 NONE block.
- An INTRA block at 128 inside an inter frame was ruled out as the cause by adding a named refusal for it
  (it is not what the stream stops on).
