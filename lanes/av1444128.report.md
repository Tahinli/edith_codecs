## What changed (decode.rs, both inter arms -- compound and single-ref; the two
arms' text was byte-identical, the patch asserts that and rewrites both)

1. **The chunk tail's chroma read is now a per-unit walk** (libaom
   `decode_token_recon_block`, decodeframe.c mu loop + `av1_get_max_uv_txsize`
   blockd.h:1361): `av1_get_max_uv_txsize(BLOCK_128X128)` = TX_32X32, and the mu
   walk enumerates EVERY TX_32X32 unit of the chunk's chroma per plane in raster
   order. At ss 0/0 the chunk's chroma is 64x64 -> FOUR units; at 4:2:0 it is
   32x32 -> the loop degenerates to the one unit the arm always coded
   (`chunk_chroma = chroma_side * 64 / side`, `units = chunk_chroma / 32` --
   derived from the existing `chroma_side`, so the patch composes with the 444
   lane's `chroma_side = side >> ss_x` threading without touching it).
2. **Per-unit geometry and stamps** (the 444 lane's continuation-8 lesson):
   each unit reads `around_mi` at its own mi origin over its own entropy-cell
   span (64 px at 4:2:0, 32 px = 8 mi cells at ss 0/0; `get_txb_ctx` reads 8
   chroma context cells either way) and `record_mi_chroma`s the unit's own grid
   immediately, so the next unit over reads this one's state. Offsets
   (`cu_x/cu_y`, the MC predictor slice, the assembled `u_units`/`v_units`
   grid placement) are all generalized off `chunk_chroma`; at 4:2:0 every
   generalized expression equals the old literal (byte-identical degenerate
   case, witnessed below).
3. **Per-unit chroma tx_type inheritance** (`av1_get_tx_type`, blockd.h:1291):
   an inter block's chroma unit inherits the coded type of the luma leaf
   covering its own quadrant (the map is read at the chroma 4x4 position scaled
   back to luma), not the block's first leaf. The arms now collect each luma
   leaf's `(row, col, tw, th, tx_type)` and resolve the cover per unit. At
   4:2:0 with unsplit TX_64X64 leaves every type is DCT_DCT and this equals the
   old `first_tx_type` pass-through (byte-identical); with split leaves the old
   code was wrong and the new code is libaom-exact. `reduce_inherited_chroma_tx_type`
   (the chroma ext-tx narrowing) is unchanged.
4. The lossless sub-arm's call now passes the generalized chunk offset/size;
   its internal per-unit walk is unchanged.
5. New regression gate
   `a_real_aomenc_128x128_none_inter_blocks_coded_chroma_per_mu_chunk_decodes_pixel_exact`
   (stream.rs): testsrc2 128x128, `--sb-size=128 --min-partition-size=64
   --max-partition-size=128 --cq-level=8 --cpu-used=2`, 12 frames; the key
   frame splits to 64x64 (detailed content) and ALL 11 inter frames are
   non-skip 128x128 PARTITION_NONE blocks. Hard census asserts
   (`inter_sb128_none_hits >= 8`, `chroma_split_tx_hits >= 64` = two units per
   plane per coded block -- measured 11 and 88) + pixel-exact via
   `decode_all_frames_vs_oracle`.

## Defect found and fixed during verification (class mixed-unit-tuple)

The vartx leaf tuple `(row, col, tw, th)` mixes units: `(row, col)` are MI,
`(tw, th)` are PIXELS (the rect-leaf path already divides by `MI`). The first
cut of the covering-leaf lookup compared the px extents as mi, so the one
non-Idtx leaf in the witness stream (DctDct at luma (64,96)) mapped its chroma
unit to the wrong type (Idtx) -- reconstruction-only corruption of exactly that
unit (~1.2k chroma samples/frame, entropy in sync, Y exact). Fixed by dividing
the leaf extents by `MI` in the predicate (`EC_LEAFDBG` scratch instrumentation
pinned it; instrument removed after).
