## Root cause (r6's open defect, closed)

`av1_get_tx_type` (`av1/common/blockd.h:1291-1305`) scales a chroma transform's
`blk_row`/`blk_col` back by the subsampling and indexes `xd->tx_type_map`.
`set_mi_offsets` (`av1/common/av1_common_int.h:1679`) re-points that pointer to
the CURRENT sub-block's mi, so for a sub-8x8 group the block current at the
chroma read is the CHROMA-REFERENCE (last) sub-block -- its first transform
unit's `tx_type` is what chroma inherits. Both sub-8x8 inter paths took the
group's FIRST sub-block:

* `crates/ec-av1/src/decode.rs:23614` (`decode_inter_sub8_split4`): `i == 0` -> `i == 3`;
* `crates/ec-av1/src/decode.rs:24598` (`decode_inter_sub8_rect2`): `idx == 0 && (i == 0 || piece[0].is_none())` -> `idx == 0 && i == 1`.

The `piece[0].is_none()` (INTRA first sub-block) special case disappears: under
the correct rule the chroma-reference block's own type is always the answer.

No chroma `tx_type` symbol is coded, so the msac stream stayed in sync and only
the inverse transform's BASIS was wrong (class `tx-type-set-membership`).

tx_type VALUES, both sides, at the defect (`~/.cache/t900-tmp/t900_h.obu`,
decode-order frame 14, luma 8x8 at (944,568) = mi(142,236) split HORZ into two
8x4 sub-blocks; the top one is skip, the bottom one codes `ADST_FLIPADST`):

| side | rung | value |
|---|---|---|
| aomdec | `EC_TXTYPE mi=143,236 plane=0 br=0 bc=0 txs=6 tx_type=7` | luma 8x4 = ADST_FLIPADST |
| aomdec | `EC_TXTYPE mi=143,236 plane=1 br=0 bc=0 txs=0 tx_type=7` | chroma 4x4 = ADST_FLIPADST |
| ours (pre-fix) | `OUR_TXTYPE plane=1 x=472 y=284 side=4 tx_type=DctDct inh=Some(DctDct)` | chroma 4x4 = DCT_DCT |

(V is absent from the oracle's list because its unit was `all_zero` -- which is
exactly why the residue was U-only.)
