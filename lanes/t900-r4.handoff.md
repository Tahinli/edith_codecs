## ROOT CAUSE 2 (fixed, `d068c94`) -- edge-filter neighbours of the FIRST half

`Neighbours::modes_above_left(r, c)` (decode.rs:5677) derives its mi-exact
lookup key from the coarse 16x16 cell: `mi_r = r * 4`, `mi_c = c * 4`. The
rect intra-in-inter site (decode.rs:7668) called it for BOTH 8x16 halves of a
PARTITION_VERT 16x16, so the second half asked for the neighbours of the
first. libaom's `above_mbmi`/`left_mbmi` are the block's own
(`mi[-mi_stride]`/`mi[-1]`), so `get_intra_edge_filter_type`
(reconintra.c:974) came out 0 where libaom has 1, and every directional half
whose real above/left neighbour was SMOOTH* filtered its edge at the wrong
strength.

Witness, decode-order frame 1, block mi(104,234) = px(936,416), 8x16,
mode 5 (D113_PRED) angle_delta -1 -> p_angle 110, tx 8x16:

* aomdec `EC_PRED ... ft=1`, `EC_PREDOUT sum=43066->41767 row0=325,321,316,...`
* ours `OUR_PRED ... ft=0 sum=41742 row0=[325,320,316,...]`
* re-running the spec walk in python from the (exact) neighbours with
  filter type 1 reproduces 41767 exactly, with type 0 reproduces 41742.
* the smoking gun (temporary `EC_FT` rung, removed):
  `mi_r=104 mi_c=232 ... above=11 mie=(11,0)` / `mi_r=104 mi_c=234 ...
  above=0 coarse=(0,0) mie=(9,0)` -- the mi-exact pair for the block's OWN
  mi is SMOOTH_PRED(9), the coarse-cell one is DC.
* the above neighbours are the two 8x32 strips at mi(96,232) SMOOTH_H(11)
  and mi(96,234) SMOOTH(9) -- aomdec prints them as `EC_PREDND` (the
  non-directional early-return), which is why they are missing from an
  `EC_PRED`-only grep.

Fix: `modes_above_left_mi(mi_r, mi_c, modes_above_left(r, c))` at
decode.rs:7668 -- the same wrapping decode.rs:26106 and `decode_leaf8`
already use. Luma frame-1 residue 1269 px -> 0.

`OUR_PRED` now also prints `ft=` so the filter type can be diffed against
aomdec's `EC_PRED ... ft=` directly.
