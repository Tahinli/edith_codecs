## TASK A — the 128 NONE residual: THREE root causes, none of them where r2 pointed

r2 read "our first TX_64X64 luma unit reads AC coefficients libaom never wrote". Measured with a
range ladder (instrumented `aomdec` `EC_TRACE_COEFF` vs our `EC_TRACE_COEFF`) that premise is
WRONG: the first luma unit is identical symbol for symbol and range for range
(`all_zero ctx=1 rng=59208 / eob=3 rng=41268 / base_eob level=5 rng=44688 / ... / rng=36616`).
The divergence is at the SECOND element of the block, and it is three separate defects:

1. **Plane order.** libaom's `decode_token_recon_block` loops 64x64 luma "mu" chunks
   (`mu_blocks_wide/high = mi_size_wide[BLOCK_64X64]`) and codes EVERY PLANE of a chunk before the
   next chunk. The oracle ladder is Y(0,0) U(0,0) V(0,0) Y(0,16) U(0,8) V(0,8) ... — Y,U,V per
   quadrant. We read all four luma units and then all chroma units. Below 128 a block is one chunk,
   so the fix (`nchunk = side/64`, luma TUs then chroma units per chunk) is byte-for-byte the old
   order at every size the decoder already handled.
2. **The chroma `txb_skip_ctx` offset.** `get_txb_ctx`: chroma ctx is
   `combine_entropy_contexts(above,left)` **+7** normally, **+10** when the plane block is LARGER
   than the transform. A 128 block's 64x64 uv plane block with TX_32X32 units is AV1's only such
   case, and our chroma table only ever carried the offset-7 rows (`txb_skip_chroma_*: [[u16;3];3]`).
   Oracle read ctx=10, we read ctx=0. Added `TXB_SKIP_CHROMA_32_BIG{,_Q0,_Q1,_Q3}` from
   `av1_default_txb_skip_cdfs[q][TX_32X32][10..13]` (token_cdfs.h, all four q contexts, verified by
   re-deriving the existing offset-7 rows from the same array), `txb_skip_chroma_32` is six rows,
   caller adds 3 when `cn > 1`.
3. **Deferred chroma context writes.** r2 recorded each chroma unit's coefficient context only
   after the whole block, so the second quadrant read ctx 10 where the oracle reads 11 (base 1 from
   its left neighbour inside the same block). Now recorded per unit inside the loop; the
   post-`record_split_luma` replay stays, because that call would otherwise clobber them whole-block.
