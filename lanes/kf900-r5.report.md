# lane-kf900 r5 report -- rect intra strips never read `use_intrabc`

Tip `a7113f5` on `lane-kf900` (parent `9a01750`). GREEN.

## Defect (chartered) and root cause

The chartered stream -- 8-bit `testsrc2=s=256x192:r=25`, cq59 cpu-used 0, rect + 1:4
partitions, `--tune-content=screen --enable-palette=1 --sb-size=64` -- decoded `OK`
(`rect4_32: horz=8 vert=8`) and every luma sample of frame 0 differed from ffmpeg.

`--tune-content=screen` sets `allow_screen_content_tools`, and the key-frame header then
sets **`allow_intrabc = 1`**. `av1_allow_intrabc` is a FRAME-level test (libaom
`decodemv.c:892`, `read_intra_frame_mode_info`): every intra block reads a `use_intrabc`
symbol after `skip`/`cdef`/`delta_q` and before `mbmi->mode`, with **no block-shape term**.
`read_intra_mode` (square leaf) and `read_intra_mode_sub8` both read it;
`read_intra_mode_rect` -- the reader for EVERY HORZ/VERT/1:4 rect strip -- did not. The
arithmetic decoder therefore desynced at the first mode symbol of the first rect block of
the frame, i.e. at mi(0,0), and every later symbol and pixel was garbage.

Decisive measurement (cross-decoder range ladder, `EC_TRACE_MODE_STEP` both sides):

```
ref  EC_ISTEP mi_row=0 mi_col=0 name=skip rng=32874   ours  ... rng=32874   (identical)
ref  EC_ISTEP mi_row=0 mi_col=0 name=mode rng=58628   ours  ... rng=62696   (diverged)
```

62696 is exactly `kf_y_mode[0][0]` symbol 0 from 32874. 58628 is that same read after ONE
default `intrabc` symbol was consumed first (32874 -> 30694 -> normalised 61388 -> 58628),
computed by hand from `od_ec_decode_cdf_q15` (`aom_dsp/entdec.c`) with
`default_intrabc_cdf = AOM_CDF2(30531)`. That is the missing symbol, not a table row.

## Changes

| path | why |
| --- | --- |
| `crates/ec-av1/src/decode.rs` `allow_intrabc_frame()` (new, next to `intrabc_hits`) | `INTRABC_MI_GRID` is `Some` exactly when the frame header set `allow_intrabc`, so the flag reaches the rect reader with no new plumbing through 5 functions |
| `crates/ec-av1/src/decode.rs` `read_intra_mode_rect`, right after `istep!("dq", 0)` | reads `use_intrabc`; refuses by name when it fires (rect intrabc reconstruction is not ported); bumps `RECT_INTRABC_READS` |
| `crates/ec-av1/src/decode.rs` `RECT_INTRABC_READS` + `rect_intrabc_reads()` / `reset_rect_intrabc_reads()` | gate hit counter: strips that READ the symbol (distinct from `INTRABC_HITS` = blocks that USE intrabc) |
| `crates/ec-av1/src/stream.rs` `rect_intrabc_reads()` re-export + new gate | gate + probe surface |
| `crates/ec-av1/src/refusal_inventory.rs` | new refusal `"intra block copy on a HORZ/VERT/1:4 rect intra strip (reconstruction is not ported at this shape)"` (45 -> 46) |
| `crates/ec-av1/examples/decode_probe.rs` | prints `rect_intrabc_reads:` |

Class sweep: `grep -n "cdfs.kf_y_mode\[" crates/ec-av1/src/decode.rs` -> 3 intra mode
readers (5630 rect, 8828 square, 10709 sub8); all three now read `cdfs.intrabc` under the
frame flag (5618 / 8807 / 10700). No other site.
