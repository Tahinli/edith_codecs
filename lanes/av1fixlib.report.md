## 2. The three invariants, as assertions

All three are in `scripts/verify-fixture-library.sh`, reported always and FAILED
under `EC_REQUIRE_FIXTURES=1`:

1. **No committed pin through the gitignored root.** The shape
   `concat!(env!("CARGO_MANIFEST_DIR"), "/../../fixtures/<file>")` can never be
   satisfied by a committed pin, so its gate skips on every clean checkout and
   every runner. A root *subdirectory* (`fixtures/audio`, `fixtures/vectors/…`)
   is deliberately NOT this shape: a generator named in the manifest produces
   those, and they are expected to be absent in a clean checkout.
   **One live violation, in a crate this lane does not own:**
   `crates/ec-av1/src/stream.rs:30271` → `/../../fixtures/lr-sgr-r7.obu`.
   The fix is one line and is now available: the pin is committed crate-local,
   so read it with `crate_pin("lr-sgr-r7.obu")`. Owner: the ec-av1 lane.
2. **Every committed pin present AND tracked.** A pin on disk but untracked dies
   with the scratchpad and its gate skips GREEN. The manifest carries a
   `tracked` column computed at generation time, so a runner host (no `.git`)
   still asserts the committed value. **Zero untracked pins today.**
3. **The `.gitignore` negation is intact** — checked statically
   (`^!crates/\*/fixtures/\*\*$`, works on a host with no `.git`) and, in a git
   tree, `git check-ignore` must not shadow any tracked pin.

Provenance is a class column, separate from the generator script, because a
recovered witness is not a re-encode:

| class | rows | meaning |
|---|---|---|
| `regenerated` | 192 | a script in the generator column reproduces the bytes |
| `captured` | 81 | committed bytes whose only provenance is a gate comment — a FINDING |
| `recovered-original` | 4 | the runner-library bytes, sha256 recorded, tracked |

Recovered-pin self-validation splits in two. This script decides the **hash
half**: every `recovered-original` row must hash to its recorded sha256, and a
re-encode fails it. The **behavioural half** is `pinned_golden7`'s
`non_last_ref_hits` 0→2, recorded in the gate's own doc; only
`cargo test -p ec-av1 pinned_golden7` proves that, and it is NOT run here — the
ec-av1 crate is mid-wave and owned elsewhere. That is the one claim in this
report I did not execute.

## 4. Four tooling defects the hosts found that local runs could not

Every one of these was invisible in my own worktree and only appeared on a host
tree (source tarball, no root `fixtures/`, library via `EC_FIXTURES`):

1. `EC_FIXTURES` did not map the bare `fixtures` root row — 15 spurious mode-ii
   failures on all three hosts, identical.
2. The drift check diffed the whole file, header included, and the header carries
   per-host state (absolute fixture root, unresolved-literal count) — so drift
   could never pass on a host whose root or library differs. Drift now compares
   the rows only.
3. The resolve anchors are `$crate`, `$ROOT`, `$ROOT/crates`; a
   `../../fixtures/…` literal tried against the latter two walks *above* the
   repo, and on a host whose parent directory holds a same-named directory the
   row was written machine-specific. Anchors now require containment.
4. The unresolved-row fallback normalised the *resolved* path instead of the
   literal, so `/home/<user>/fixtures/audio` lost its leading slash and became
   the row `home/<user>/fixtures/audio` — a path no other host can match, i.e.
   silent DRIFT everywhere except the generator. Three rounds to find; it is the
   reason the first two host rounds were RED for reasons that were not drift.

Each is a separate commit with the host evidence named.

## 7. Addendum: the pin-reading GATE census (the invariant I first shipped was too weak)

The invariant Main handed me — "every `crate_pin("X")` must have
`crates/<crate>/fixtures/X`" — matches only single-name call shapes. It is blind
to the shape that actually exists in the crate: `pinned_warp_stream_decodes_pixel_exact`
(`crates/ec-av1/src/stream.rs:31099`) reads **fourteen** pins through a directory
literal plus a runtime name list,

```rust
let fixtures = concat!(env!("CARGO_MANIFEST_DIR"), "/../../fixtures");
["warp-mismatch", "warp-flake-5", ..., "rect-flake-3"]        // comments between items
    .iter().map(|n| format!("{fixtures}/{n}.obu"))
```

and **zero** of those fourteen are committed under the crate. The gate is
`#[ignore]`d, so today it is a no-op that reports nothing — it will not go red,
it just will not run. A preflight that passes it is the silent shape again.

`scripts/pin-gate-audit.py` (new, committed) closes it:

1. resolves `concat!` / `Path::new(env!(...)).join(...)` root literals, **strips
   line comments** before parsing the name list (the comments between items are
   why a bracket-shaped parse silently misses it), anchors on the `format!` that
   consumes the list, and enumerates every runtime name built from that root.
2. a bare directory literal feeding a runtime name list **always** fails: no
   committed tree can satisfy names chosen at runtime.
3. prints the census as numbers:
   `total=8 committed=7 uncommitted=14 ignored=3 assertless=0` — identical on
   the local tree and on all three runner hosts.
4. classification follows the **helper call graph**, not the gate body. The warp
   gate has no `assert` in its body but calls `check_pinned_warp_stream`
   (`stream.rs:31226`), which asserts luma, U and V per frame, so it is reported
   as `via-check_pinned_warp_stream`. A body-only read calls it assertless —
   the exact misclassification made earlier today, and the reason the audit
   resolves helpers instead of reading bodies.

Three of the four single-literal pin gates now resolve through committed copies
**because this lane recovered them** (`golden6-mismatch.obu`,
`golden7-forwarding-mismatch.obu`, `lr-sgr-r7.obu`, plus `golden4-pin.obu`):
that is where `committed=7` comes from.
