# lane-kf1200 r1 — the 16x4/4x16 chroma pair read its edge-filter type from the wrong mi

## Defect (census4 premise, re-measured on this branch)

Hunger Games `-ss 1200` key frame (1 frame, `3840x1608 yuv420p10le`), our
`EC_PROBE_OUT16` vs `ffmpeg -pix_fmt yuv420p10le`: **12 U samples at ±1, Y and V exact**.
Stage bisect (`EC_AV1_PREFILT_DUMP16` ours vs aomdec's): **13 U samples already wrong
before the loop filter** — a reconstruction defect, not deblock/CDEF/LR/film grain, and
not an entropy desync (lane-kf900's shape).

## Root cause

Block: chroma `(x=352, y=356)`, `8x4`, `uv_mode = H_PRED`, `angle_delta_uv = -2`
(`p_angle = 174`), the chroma half of a `16x8` **`PARTITION_HORZ_4` pair** at
luma mi `(178,176)`, strip mi `(179,176)`.
Its prediction differed from aomdec's by 4 samples of the last row
(`OUR_PRED sum=16208` vs `EC_PREDOUT sum=16212`); row 0 and column 0 identical.

`decode.rs:7683` asked for the chroma edge-filter type at the **strip's own mi**
(`lmi = (179,176)`). libaom builds `chroma_above_mbmi`/`chroma_left_mbmi` from
`mi[-((mi_row & ss_y) * mi_stride + (mi_col & ss_x))]` (`set_mi_offsets`,
`av1/common/blockd.h`), i.e. from the **pair's base mi** `(178,176)`, and
`get_intra_edge_filter_type` (`av1/common/reconintra.c:974`) reads that block's
`uv_mode`. The mi directly above the strip, `(178,176)`, is a non-chroma-reference
4-row block whose `uv_mode` is `UV_DC_PRED`; the mi above the PAIR, `(177,176)`,
coded `uv_mode = SMOOTH` (aomdec `EC_IMODE_VAL mi_row=177 mi_col=176 uv_mode=9`).

So we computed `filt_type = 0` where libaom has `1` (aomdec `EC_PRED ... ft=1`).
With `filt_type = 0`, `av1_use_intra_edge_upsample(4, 8, -6, 0)` is TRUE
(`blk_wh = 12 <= 16`) instead of false — the left edge was upsampled before the
z2 walk, moving 4 samples by 1. The strength/upsample/z2 code itself is correct:
recomputing z2 by hand from the (identical) neighbour pixels reproduces aomdec's
row exactly (`scratchpad/kf1200`, brute force over dy/offsets).

## Change

- `crates/ec-av1/src/decode.rs:7683` — `smooth_uv_neighbour(pair_mi.0, pair_mi.1, ...)`
  instead of `(lmi.0, lmi.1, ...)`, with the libaom citation.
- `crates/ec-av1/src/decode.rs:2196` — new `RECT4_16_UV_PAIR_FILT_HITS` counter +
  `rect4_16_uv_pair_filt_hits()`: pairs where the pair-base answer DIFFERS from the
  strip-mi answer, i.e. the blocks the fix changes.
- `crates/ec-av1/src/stream.rs` gate
  `a_real_aomenc_stream_with_a_16_level_1to4_partition_decodes_pixel_exact` — the odd
  attempts now use a **chroma-carrying** source (smooth `cb`/`cr` gradients); the gray
  source left both chroma planes constant, so every `uv_mode` was DC and the shape was
  unreachable. New hard assert: `pair_filt_proved > 0` per bit-depth arm.

No refusal lifted, so `refusal_inventory.rs`/`gate_coverage.rs` are unchanged.
