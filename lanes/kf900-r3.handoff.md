## 1. The silent 10-bit desync -- ROOT CAUSE FOUND AND FIXED

Stream: `testsrc2=s=256x192 --bit-depth=10 --cq-level=59 --cpu-used=0`, recipe
`$HOME/.cache/kf900/sweep/sweep.sh`, md5 `e5f033d8fe34e4418d8cca3ac9d2b595`
(`$HOME/.cache/kf900/sweep/g.obu`).

Symbol: the FIRST block's Y palette colours. mi(0,0) is BLOCK_32X16, DC_PRED,
2-colour Y palette. `decode.rs::read_palette_colors_y` / `read_palette_colors_uv`
read every raw literal at a hardcoded 8 bits; libaom `decodemv.c:478` (Y) and
`:509` (UV) size them all by the sequence `bit_depth`: first colour
`aom_read_literal(r, bit_depth)`, `min_bits = bit_depth - 3` (Y/U) and
`bit_depth - 4` (V delta mode), `range = (1 << bit_depth) - first - 1` (Y) /
`- first` (U), clamp bound `(1 << bit_depth) - 1`, V wrap modulus `1 << bit_depth`.
So a 10-bit palette block read TWO BITS TOO FEW per transmitted colour and decoded
the whole rest of the tile from the wrong bit position, with no refusal.

Fix (commit `667eb51`): `let bd = u32::from(bit_depth());` (the already-present
thread-local, decode.rs:200) inside both readers; no signature threading.

Before: `OK: 1 frames decoded` with 73687/73728 samples differing from ffmpeg,
max |d| 933 (Y 49117/49152, U 12286/12288, V 12284/12288, first diff at (0,0)).
After: the entropy stream is in lockstep with aomdec -- our first 1024
`EC_PAL`/`EC_PAL_VAL` lines are byte-identical to aomdec's `EC_TRACE_PALETTE`, and
the block grid follows aomdec's (`EC_IMODE` mi(0,0) 32x16, (4,0) 16x16, (4,4) 16x16,
(0,8) 32x8, (2,8) 32x8, (4,8) 32x8 == aomdec bsize 8,6,6,19,19,19).

WHY 108 SWEEP RECIPES AND A RANGE LADDER MISSED IT: raw literals are EQUIPROBABLE
and at the ranges this content reaches an equiprobable read is a FIXED POINT of the
msac range (62728 -> v=31364, either branch 31364, renorm 62728). A cross-decoder
RANGE ladder stays bit-identical straight through a wrong literal WIDTH; only the
decoded VALUE moves. aomdec and we both printed `rng=62728` and disagreed on the
first colour index (0 vs 1). Compare VALUES, not range alone.

This stream is NOT a whole-frame gate: at mi(4,8) it hits a 32x8 (4:1) strip that
really uses a palette, and the 1:4 rect decoder is called with `palette: None`
(decode.rs:7167 and :7556), so it now stops at the pre-existing refusal
`"a 1:4 rect strip that actually uses a palette (reconstruction is not ported at
this shape)"`. Silent desync -> named refusal.
