## Root cause of the r6 "last superblock" residue (found, fixed)
Stream `$HOME/.cache/kf900-r6/DIFF_55_0_1_test.obu` (testsrc2 256x192 cq55 txs=0 palette=1
screen 8-bit). The r6 report's "entropy stays in sync, reconstruction defect, deltas ~4" was
WRONG on both counts: deltas run to +-171 and it is an ENTROPY desync -- invisible because the
bad block sits in the LAST superblock, so nothing after it could disagree.

* Stage: mode info -> first coefficient TU. Cross-decoder `EC_TRACE_MODE_STEP` ladder diverges
  at mi(34,52) (luma 136,208): both decoders read skip/cdef/dq at rng=42705, then the next
  block starts at oracle rng=52073 vs ours 33144.
* Block: an 8x8 **leaf** (`decode_leaf8`) that decoded `use_intrabc=1`, DV `(-512,-1360)`
  (identical on both sides -- `EC_TRACE_IBC`, so the DV read is exonerated for the 3rd time).
* Element: the luma `tx_type`. `EC_TRACE_COEFF` (our trace now prints the CDF width, `len=`):
  ours read an 8-slot row (`TX_SET_INTRA_1`, 7 symbols), libaom reads
  `av1_get_ext_tx_set_type(TX_8X8, is_inter=1, 0)` = `EXT_TX_SET_ALL16` (16 symbols), because
  `is_inter_block(mbmi)` counts `is_intrabc_block` (`av1/common/blockd.h:373`, set chooser
  `av1/common/blockd.h` `av1_get_tx_type`). Same value, different interval -- class
  `wrong-alphabet-same-value`.
* Why only there: `decode_leaf8` consumed `use_intrabc` + the DV through `read_intra_mode` and
  then ignored the result entirely -- no inter ext-tx set, no chroma tx_type inheritance, no
  prediction from the current frame, no `record_intrabc_mi`. `decode_block` (16x16 and up) had
  all four since r6.

## Fix (crates/ec-av1/src/decode.rs, `decode_leaf8`)
1. take `INTRABC_DV`; refuse under `TxMode::Select && !skip` with `decode_block`'s EXISTING
   refusal string (no new inventory entry); a skipped intrabc leaf reads no intra `tx_depth`.
2. luma set `txbset_for_inter(8, reduced_tx_set)`.
3. BILINEAR prediction from the current frame at the DV (8x8 luma, 4x4 chroma) through the
   `PALETTE_PRED` override slot, in both the skip and non-skip branches.
4. `INTRABC_CHROMA_TX` armed after the luma read and **disarmed** after the V read (leaving it
   armed leaked the luma tx_type into every later chroma block: 320 chroma samples wrong,
   luma exact -- second bug, found by re-measuring).
5. `record_intrabc_mi(leaf_mi, 2, intrabc_dv)` on both exits (a later DV's MV stack).
Plus counter `LEAF8_INTRABC_HITS` + `stream::leaf8_intrabc_hits()` + a `decode_probe` line.

Measured, 8-bit `$HOME/.cache/kf900-r7/S_DIFF_test_55_r0_d8.obu` (same source/cq, rect+1:4 off
so no rect-strip refusal fires first): before 320 chroma samples wrong / entropy desync at the
leaf; after **0 bytes differ vs ffmpeg** (`cmp -l` = 0), `leaf8_intrabc_hits=1`, and the
`all_zero`/`eob` range ladder is identical for all 499 steps.
The ORIGINAL r6 stream now stops earlier at the pre-existing named refusal
"intra block copy on a HORZ/VERT/1:4 rect intra strip" instead of decoding wrong pixels.
