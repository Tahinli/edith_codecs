# lane-b64b — the 64x64 root: compound, var-tx, edge, intra

Branch `lane-b64b`, base `12a8c4a7`. Scope: `crates/ec-av1/src/encode.rs`'s 64
root (`search_skip_64`, its residual arm, `sb64_legal`), `tile.rs`'s
`Quadrant::Whole64` writer arm, tests.

## Step 1 — COMPOUND references at the 64 root (commit `b9a4d589`)

Search: `search_skip_64` takes this superblock's `LAST` + GOLDEN/ALTREF
compound stacks (`find_mv_stack_compound` at the 16x16-mi window the writer
rebuilds from) and prices three modes — `NEAREST_NEARESTMV`,
`GLOBAL_GLOBALMV`, `NEW_NEARESTMV` — through `predict_compound_u8`, a heap
counterpart of `predict_u8` on the same `predict_compound_intermediate` +
`combine_compound` path (`mc_trial_compound`'s fixed buffers are sized for a
32x32 block, so they cannot serve a 64 root). Every candidate is compared
against the single-reference arm at ONE syntax price: `fixed` minus the single
reference tree, plus the pair tree and the compound mode symbol.

DEVIATION from the charter, named: `NEAREST_NEWMV` and `NEW_NEWMV` are NOT
offered. Both need the SECOND reference's own `NEWMV` vector, which only a
second 64x64 motion search per superblock produces — the wall this root exists
to save (`b64_residual`'s doc: a root that wins is four quadrant searches that
never run). The three modes above cost no extra search.

Writer: the `Whole64` arm's "a 64x64 root block is coded single-reference"
refusal is gone; a compound root codes `comp_mode` 1 and the whole
`write_compound_block` chain at `(bw4, bh4) = (16, 16)`, publishes both
references and both vectors into the MI grid, writes NO `motion_mode` symbol
(libaom's `motion_mode_allowed` refuses a compound block) and stamps
`record_block_compound` so the next block reads the right compound contexts.

`EC_AV1_B64COMP=0` restores the single-reference root, so both arms measure on
one build.

### Exactness

`encoder::tests::a_crossfade_clip_codes_a_compound_64x64_root_and_decodes_sample_exact`

## Step 2 — depth-1 var-tx under the 64 root (commit `484c390e`)

`commit_inter_luma` -- the var-tx decision every other inter block already
takes -- reaches side 64 now: its halved transform is TX_32X32
(`TxbSet::Luma32Inter`), and the eligibility line that read `side < BLOCK ||
tx32_depth_search()` reads `side != BLOCK || ...` so a 64 root is offered the
trial while the 32x32 knob keeps meaning what it meant. The root's own
counter (`take_b64_var_tx_hits`) keeps it out of the depth census's leaf row.
The writer's `Whole64` arm codes `txfm_split = usize::from(block.tx_depth)`
and, at depth 1, the four TX_32X32 units `write_luma_tus` slices out of the
block's 64x64 levels (its "a 64x64 block's split luma transform is not
written yet" refusal now only covers a split finer than TX_32X32); the pricer
(`predicted_coeff_bits`) slices the same four units in the same diff.

`EC_AV1_B64VARTX=0` restores the single TX_64X64.

## Step 3 — EDGE superblocks (commit pending)

`sb64_legal` required the WHOLE superblock inside the true frame. AV1 asks
only that the block's own half is (`has_cols`/`has_rows`, spec
`decode_partition`), and the writer's `Whole64` arm already refuses exactly
the other case, so the missing half was the SEARCH's: a trial scored over the
padding the encoder invented past the edge. `inside_sse` scores the inside
part alone and `clip_sb64_sse` rescores all three planes of every 64-root
trial set (skip, compound and residual arms) when the edge cuts the
superblock. The root's var-tx arm stays off there by `commit_inter_luma`'s own
"wholly inside" rule, so an edge root is one TX_64X64 or a skip.

`EC_AV1_B64EDGE=0` restores the old rule.

### Exactness

`encoder::tests::a_non_superblock_aligned_clip_codes_edge_64x64_roots_and_decodes_sample_exact`
— 232x168 (mi 58x42: the last superblock column and row are cut with more
than half inside): 9 edge roots, every frame sample-exact through our decoder
AND ffmpeg.

### 12-frame gate

The gate CANNOT see this step: film A is 1920x768 (mi 480x192), film B and
the screen capture are 1920x1024 (mi 480x256) — every row is superblock
aligned, so `take_b64_edge_hits` is 0 on all five and the shipped table below
is identical to step 2's ON arm. The decision rests on the synthetic
exactness test above plus the fact that it is the user's arbitrary export
sizes, not the gate clips, that reach the path (class
`gate-blind-to-feature`, stated rather than hidden).

DECISION: **KEEP, default on** — no gate row moves, one new capability, one
witness.

## Step 4 — INTRA 64x64 root

NOT IMPLEMENTED this round. `Superblock::Whole` is produced nowhere but three
unit tests (`tile.rs:8024/8142/8710`), so the key-frame search would need a
whole-superblock intra candidate (13 modes at 64x64, TX_64X64 luma plus two
TX_32X32 chroma), its own `Superblock::Whole` assembly in the key search's
block list, and the pricer's key-frame arm — a diff the size of steps 1 and 2
together, which did not fit this lane's budget after three gate rounds.

`deferred: the intra 64x64 root on key frames — the key-frame search has no
whole-superblock candidate at all and the change is not a variant of the
inter root's — unblocks: one lane scoped to the key search plus
`sb_coeff_key_frame_tile`'s `Superblock::Whole` arm, gated on the key-frame
share of the film rows (a 12-frame gate at gop 12 codes one key frame in
twelve, so the long-GOP arm is the honest one for it).`
