# lane-t900 r12 handoff -- the chroma edge-filter type read a one-slot-per-column uv_mode map; a sub-8x8 pair overwrote its own neighbour row

Tip: `a75db293` on `lane-t900` (base: main `2b65cb8e`, fast-forwarded in before any edit).

## Target A -- 4K 10 s head, decode frame 161: ROOT CAUSE FOUND AND FIXED

Stage split first (r11 method rule), BEFORE reading any prediction code:
`EC_AV1_PREFILT_DUMP16` on both decoders over a 250-OBU / 168-decode-frame cut of the
10 s head (`~/.cache/t900-tmp/hg250.obu`) -- the mismatch is already in RECONSTRUCTION
(pre-filter), frames 161 and 162 only, and it is **CHROMA ONLY, luma bit-exact**:

    f161 U 37 px, V 22 px, deltas -3..+3, in three anti-diagonal triangles at
         chroma (856,160), (1080,252), (1088,696)

Block: chroma (856,160) = luma mi(80,429), a 4x8 luma leaf (PARTITION_VERT of an 8x8),
i.e. the CHROMA-REFERENCE half of a sub-8x8 pair. `EC_PRED` on both decoders
(ours needs `EC_PICT` under `EC_PRED`, added this round, decode.rs:29684 -- the second
of the two EC_PICT sites is the inter-frame one):

    aomdec  EC_PRED mi_row=80 mi_col=429 plane=1 txw=4 txh=4 mode=3 p_angle=45
            have_top=1 have_left=1 n_top=4 n_left=4 n_tr=4 n_bl=-1 bsize=3 part=2 ft=1
            EC_PREDOUT sum=8355 row0=514,521,523,523
    ours    OUR_PRED x=856 y=160 side=4 mode=3 ad=0 ft=0 sum=8358 row0=[514,524,522,523]

One field: `ft` (intra_edge_filter_type) 1 vs 0. Same mode, same angle, same edges.

Root cause (`decode.rs` `Neighbours::smooth_uv_neighbour_unsnapped`): libaom reads the
chroma neighbours straight off the mi grid (`chroma_above_mbmi = base_mi[-stride]`,
`set_mi_row_col`), where every mi cell a block covers holds that block's `uv_mode`.
Ours kept only ONE slot per mi column (`uv_mode_col[col] = (last_row, uv_mode)`), so
inside a sub-8x8 pair the pair's own FIRST half (mi(80,428), non-chroma-ref, stamps
DC_PRED over mi rows 80..81) overwrote column 428 before the pair's chroma-ref half
(mi(80,429), which snaps its neighbour read to base column 428) read it. The mi-exact
match `row == mi_r - 1` then failed and the coarse SUB-grid band answered DC instead of
the SMOOTH_PRED chroma block really sitting at mi(79,428) -- `ft` 1 -> 0, which flips
`av1_use_intra_edge_upsample`/filter strength on the chroma edge.

Fix: `uv_mode_grid`, a full mi-granular `uv_mode` grid (superblock-padded stride
`uv_grid_cols`, `u8::MAX` = unwritten) written by `record_uv_mode_mi` over every cell a
block covers and read first by `smooth_uv_neighbour_unsnapped`; the two old maps stay as
the fallback for unwritten cells, so no existing path changes answer unless the grid
knows better. Availability stays tile-relative (`mi_r > tile_row0_mi` /
`mi_c > tile_col0_mi`, untouched); the grid is per-frame (`Neighbours::new`).
New counter `ec_av1::decode::uv_mode_grid_override_hits()`.

## Method notes for the successor

* Our `EC_PICT idx=N` marker is printed at the END of frame N's decode, so a frame's
  trace lines are the ones BEFORE its marker, not after (an r11/r12 off-by-one that
  silently reads the next frame).
* `EC_PICT` now also prints under `EC_PRED` (both sites).
* aomdec has no frame marker; align its `EC_PRED` lines by grepping a small mi window
  in both decoders and matching the sequences 1:1 -- an UNMATCHED extra line on our side
  is itself the finding.
