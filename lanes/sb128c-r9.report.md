# lane-sb128c r9 -- the four AB shapes at the 128 root (key + inter)

Branch `lane-sb128c`, worktree `edith_codecs-sb128c`,
`CARGO_TARGET_DIR=$HOME/.cache/cargo-target-sb128c`.

## What changed

- `crates/ec-av1/src/decode.rs` `read_sb128_root`: the AB refusal is LIFTED.
  Values 4..7 now count into `PART128_AB_HITS` (`part128_ab_hits()`), and the
  `_` arm refuses only a value outside the 8-symbol alphabet.
- `crates/ec-av1/src/decode.rs` key-frame tile: a new arm decodes each AB
  shape as two 64x64 squares (`decode_block`, `SB`, `Luma64`/`Chroma32`) plus
  one 128x64/64x128 half (`decode_block_128rect`, r8) in libaom
  `decode_partition`'s order -- HORZ_A = TL, TR, bottom half; HORZ_B = top
  half, BL, BR; VERT_A = TL, BL, right half; VERT_B = left half, TR, BR --
  with `Reach::vert_ab_partition` live for the two VERT arms (r6 visit order,
  class `visit-order-changes-availability`), `CDEF_TRANSMITTED` reset per
  piece (one CDEF unit each, so libaom's per-unit `cdef_transmitted[index]`),
  and the half's `cdef_idx` copied to the second 64x64 unit it covers.
- `crates/ec-av1/src/decode.rs` inter tile: the same four arms through
  `inter_piece!` (`SB`/`SB*2` with `ww`/`wh` = the true footprint).
- `crates/ec-av1/src/stream.rs` `sb128_ab_counters()`; new gate
  `a_real_aomenc_sb128_ab_partition_at_the_128_root_decodes_pixel_exact`.
- `crates/ec-av1/src/refusal_inventory.rs`: the 128-root AB string is replaced
  by the alphabet-bound one.

fails on its FIRST arm: `sb128c-ab-18-512x512` decode-order frame 0 differs
from the oracle at byte 319 (ours 105 vs 107), 326839 bytes differ.

`partition_w128` values for its 16 roots are 2,2,2,0,0,3,3,0,... ; the first
value in 4..7 is the 38th root, i.e. frame 2). The first differing sample is
(x=317..319, y=0), inside the LEFT 64x128 half of the third 128 root, which is
`PARTITION_VERT` -- r8's `decode_block_128rect`, untouched this round.
