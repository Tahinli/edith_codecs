## What changed

* `crates/ec-av1/src/decode.rs` -- `decode_rect4_16` (new): the four strips of a
  16-level `PARTITION_HORZ_4`/`VERT_4`, wired at the key-frame 16-level
  partition site (the old refusal is now
  "a 16x16-level partition value outside PARTITION_NONE..PARTITION_VERT_4",
  the SB-level wording one size down).
  - CHROMA is what is new at this size: `is_chroma_reference` is false for a
    4:2:0 block one mi tall (wide) on an EVEN mi row (column), so strips 0 and 2
    read no `uv_mode`/`cfl_alpha`/`angle_delta_uv` and code no chroma; strips 1
    and 3 close the pair and carry the 8x4 (4x8) chroma of the whole 16x8 (8x16)
    luma pair at the PAIR's origin (`setup_pred_plane`'s `mi_row -= 1`), CfL
    averaging the pair's luma.
  - `read_intra_mode_rect` grew a `has_chroma` (`is_chroma_reference`) parameter;
    the four existing call sites pass `true`.
  - Split transform: `decode_rect_split`'s per-unit walk inlined (its chroma is
    the block's, ours is the pair's). depth 1 = TX_8X4/TX_4X8 rect units
    (`TxbSet::LumaRect4x8`), depth 2 = square TX_4X4 via `read_plane`.
  - `filter_intra_size_class_rect`: classes 12/13 for 16x4/4x16.
  - `palette_bsize_ctx_wh`: DEFECT SWEPT -- `av1_allow_palette`'s
    `sb_type >= BLOCK_8X8` is an ENUM INDEX test that BLOCK_4X16 (16) and
    BLOCK_16X4 (17) clear, so a 64-pixel 1:4 strip DOES read `palette_y_mode`
    (ctx 0) in a screen-content frame; the old "both sides >= 8" bound dropped
    that symbol. Now `bw <= 64 && bh <= 64 && bw * bh >= 64`, which reproduces
    the enum-index rule for every shape.
* `crates/ec-av1/src/cdf.rs` -- `FILTER_INTRA` rows 12/13 (10368/12770), the
  values `filter_intra_classes_carry_their_own_libaom_default_row` already
  pinned for BLOCK_16X4/BLOCK_4X16; that test now lists both as owning a class.
* `crates/ec-av1/src/cdf_state.rs` -- `TxbSet::LumaRect16x4{,Set1}`: `Luma8`'s
  coefficient tables (`get_txsize_entropy_ctx(TX_16X4)` = the 8x8 class, 64
  positions) with the `TX_4X4` `tx_type` row.
* `crates/ec-av1/src/refusal_inventory.rs` -- the 1:4-below-16x16 refusal is
  gone; the 16-level partition-value guard replaces it.
* `crates/ec-av1/src/stream.rs` -- the gate.

## Gate

`a_real_aomenc_stream_with_a_16_level_1to4_partition_decodes_pixel_exact`
(4-pixel bands, transposed per attempt, explicit-seed noise, 192x128,
`--enable-1to4-partitions=1 --enable-rect-partitions=1 --enable-ab-partitions=0
--min-partition-size=4 --max-partition-size=16 --enable-filter-intra=1
--cpu-used=0`, second half of the window `--enable-tx-size-search=1`), 8 seeds x
2 tx-search arms x 2 bit depths.

```
systemd-run --user --scope -q -p MemoryMax=8G env CARGO_TARGET_DIR=$HOME/.cache/cargo-target-r14 \
  EC_NOMEMGUARD=1 EC_AV1_REQUIRE_AOMENC=1 nice -n 10 cargo test -p ec-av1 --lib -j3 \
  a_real_aomenc_stream_with_a_16_level_1to4 -- --nocapture
```

Result (both green):

* 8-bit: 15 compared attempts, 192 16x4 / 288 4x16 strips, 240 chroma pairs,
  486 coded units, 102 split-transform strips, 0 refusals, 1 out of scope.
* 10-bit: 16 compared attempts, 148 16x4 / 280 4x16 strips, 214 chroma pairs,
  433 coded units, 82 split-transform strips, 0 refusals, 0 out of scope.

Every decoded frame is pixel-compared against ffmpeg (`assert_eq` on all three
planes); a decode error is asserted to be a NAMED refusal, never a SKIP.

EVIDENCE: cargo test output above | 31 real aomenc streams encoded, decoded and compared | 340 16x4 + 568 4x16 strips, 454 chroma pairs, 184 split-transform strips, 0 mismatches
