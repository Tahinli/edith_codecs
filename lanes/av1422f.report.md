# lane-av1-422f — square-block chroma is the plane block's own rect unit; refusal stays

## Outcome

STOP with the 4:2:2 header refusal in place, byte-identical (probe refuses
without the env; the local bypass was reverted before commit). The
square-block path (decode.rs's `(luma_set, chroma_set, luma_tx, chroma_tx,
scans)` selection, formerly 16704-16721) now models `av1_get_max_uv_txsize`
as `av1_get_adjusted_tx_size(max_txsize_rect_lookup[plane_bsize])` — the RECT
that fills the (side/2, side) plane block — and all three chroma walks read
one `(chroma_tx, chroma_tx_h)` unit per grid cell, keyed on ss (1,0). The
av1422e first miss (mi(4,4) side 16: ours two 8x8 units, oracle one TX_8X16)
is gone, and the decode now aligns with the oracle unit-for-unit through 117
coefficient units — every 16x16 block's U/V TX_8X16 pair, every 8x8 leaf's
U/V TX_4X8 pair, every 16x8 strip's 8x8-square chroma — with equal entry rngs
wherever ours prints them. The stream is not pixel-exact: the next divergence
is the sub-8x8 4x4-leaf chroma at 4:2:2 (TX_4X4 units, one per even-column
leaf), which lives in `decode_leaf_split4`/`decode_leaf8` — other lanes — so
the refusal is retained.

## Change (decode.rs + decode_probe.rs only)

- Selection arm at ss (1,0): per-axis unit dims `chroma_tx` (width) x
  `chroma_tx_h` (height) — 4 -> (4,4), 8 -> (4,8), 16 -> (8,16), 32 ->
  (16,32), 64/128 -> (32,32) — with the unit's TxbSet/scan:
  `ChromaRect8x4`+`SCAN_4X8`, `ChromaRect16x8`+`SCAN_8X16`,
  `ChromaRect32x16`+`SCAN_16X32`, `Chroma32`+scan32. The destructure gains
  `chroma_tx_h`; 4:2:0/4:4:4/lossless arms carry `chroma_tx` twice, so their
  walks are untouched.
- New `read_rect_chroma_unit`: one rect chroma unit via the
  `read_coeffs_rect` route (the `chroma_tiled` arm's and
  `leaf8_chroma422_unit`'s proven shape): `txb_skip_ctx` = above+left in the
  offset-7 rows (the unit covers the plane block exactly, so no +3), the
  mode-derived default `tx_type` unless `INTRABC_CHROMA_TX` is armed, the
  `side >= 32` DCT_DCT clamp, `dequant_and_inverse_typed_wh` +
  `push_intra_rect`. Bumps the new `CHROMA422_RECT_HITS` witness counter
  (keyed ss (1,0), unit w != h).
- New `push_intra_unit`: `push_intra` when square, `push_intra_rect` when
  rect — used by the skip walk.
- All three chroma walks (skip, single-TU, chunked) key on the per-axis
  unit dims: `cn_rows = chroma_height / chroma_tx_h`, `luma_span_y =
  chroma_tx_h << ss_y`, per-axis cu positions and palette windows. Below
  side 64 a 4:2:2 frame's grid is 1x1 and the one unit is the whole plane
  block. The chunked walk's edge clip computes `max_units_h` per axis at
  ss (1,0) (the shared halved formula assumes a subsampled height and would
  clip units libaom codes); the shared rows stay for 4:2:0/4:4:4.
- New `Neighbours::around_mi_422_chroma` for the square path's chroma context
  reads: libaom `get_txb_ctx_general` sums its dc-sign votes over
  `txb_w_unit` CHROMA 4-px cells, and at ss_x 1 one chroma cell spans TWO
  luma mi columns — the per-luma-mi sum double-counts the above votes and
  flips `dc_sign_ctx` when the above and left votes have opposite signs
  (measured at mi(4,4) plane 1: ours read `dc_sign_cdf[1]`, the oracle row
  0). Sampling every second above cell counts each chroma column once, which
  is exactly libaom's sum; the level booleans are ORs over duplicated cells
  and cannot change. Used by the single-TU walk's rect branch and both
  multi-unit loops at ss (1,0) only; 4:2:0/4:4:4 keep `around_mi_rect`.
- `examples/decode_probe.rs`: prints `chroma422_rect`.

Untouched: `decode_leaf8`, `decode_leaf_split4`, `decode_rect4_16_strip`,
`decode_block_128rect`, `decode_rect_split`, the resize header reader, the
frame-9 filter path, and refusal_inventory.rs (the refusal string is
byte-identical; the gate stays green).

## First remaining divergence (named next site, with oracle evidence)

At the 8x8 sub8 group whose leaves sit at mi(8,10)/(8,11)/(9,10)/(9,11): the
oracle's 4x4 LEAVES at even mi columns are chroma references at 4:2:2 and
each codes a TX_4X4 chroma unit (mi(9,10) plane 1, 38 steps, after only its
own luma) — `ss_size_lookup[BLOCK_4X4][1][0]` is BLOCK_4X4, so the 2x4 plane
rounds up and reads as TX_4X4. Ours reads the leaf's second luma TX_4X4 as
all-zero where the oracle codes coefficients (oracle 16 steps, ours 1), the
first value-level divergence, and everything after is desynced; the run then
ends at `decode_rect4_16_strip`'s closed-shape panic (shape-driven, reached
by the same partition walk). Both sites live in `decode_leaf_split4` /
`decode_leaf8` / `decode_rect4_16_strip` — other lanes. The sub-8x8 4:2:2
model needs the is_chroma_ref rule `!(mi_col & ss_x)` (every even-column
leaf, not 4:2:0's single bottom-right leaf) plus the TX_4X4 chroma shape.
