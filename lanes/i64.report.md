# lane-i64 — the KEY frame's 64x64 intra root

Branch `lane-i64`, base `7b0e08b9`. Scope: `crates/ec-av1/src/encode.rs`'s
key-frame partition search, the pieces of `code_square`/`search_chroma` a
64-sided block needs, `speed.rs`, tests.

## What landed

The key search offers the whole superblock as ONE intra block before it
searches the four 32x32 quadrants, and takes whichever costs less at one
lambda — the shape the inter frame's 64 root (`search_skip_64`) already had.

* `code_square` reaches `side == SUPERBLOCK`: `TxbSet::Luma64` (the coded
  32x32 corner `code_from_prediction` already hands back for a 64-point
  transform) plus one `TxbSet::Chroma32` per chroma plane — exactly the three
  sets the writer's `Superblock::Whole` arm codes.
* Every mode the 32 search offers, angle-delta refinement included (the
  machinery is side-generic). No CfL (`search_chroma` gates at `side <= 32`,
  spec `is_cfl_allowed`), no filter intra (`filter_intra_size_class` has no 64
  row), no transform-depth split (the writer's arm takes a 32-sided level
  grid, so only depth 0 is representable) — the block still PAYS its
  `TX_SIZE_CAT3` zero so the 64-vs-four-32 comparison is fair.
* Three defects the 64 side exposed, each a real bound and not a new feature:
  the intra edge buffers were sized `2 * BLOCK` (a 64-wide block reads up to
  128 samples above), `intra_predict_u8`'s scratch topped out at
  `BLOCK * BLOCK`, and `search_chroma` handed a 32x32 chroma transform an ADST
  type — `av1_get_ext_tx_set_type` resolves chroma at `tx_size_sqr >=
  TX_32X32` to `EXT_TX_SET_DCTONLY`, which the DECODER already did
  (`decode.rs`'s `side >= 32` arm) and the transform asserts.
* Early-out: `split_rd_breakout_at(b64_breakout_threshold(), ...)`, the same
  preset-CLAMPED 0.125 the inter root uses, so a looser `SPLIT_RD` at a high
  preset never withholds four quadrant searches here either.
* Refused on an `allow_intrabc` frame: the quadrant searches carry DV state
  (`Ibc::last_dv`) that a discarded trial would desync.
* `EC_AV1_I64=0` in any build; `speed::I64_ROOT` on at every preset.

## Exactness witness

`encode::tests::a_smooth_gradient_key_frame_codes_whole_superblocks_and_decodes_exactly`
— a 256x192 smooth gradient at q120: **12 of 12** superblocks coded as one
64x64 intra root, and both our decoder and ffmpeg produce the encoder's own
reconstruction sample-exact on all three planes.

## Pricer

`crate::tile::predicted_coeff_bits_sb` already carried the `Superblock::Whole`
arm (Luma64 + two Chroma32, lane-tx64 wrote it for exactly this shape), so the
variant needed no new price; `predicted_coeff_bits_track_the_tile_the_writer_wrote`
is green.
