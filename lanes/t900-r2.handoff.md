Publication per exit: NOT one write per exit, but every write is IDENTICAL.

## STEP 2 -- ROOT CAUSE FOUND AND FIXED (commit after this file)

The in-inter `tx_depth` CDF row of a 1:4 strip came from the KEY FRAME's
deblock-grid approximation (`tx_size_context_rect`) instead of the real
`TXFM_CONTEXT` bands (`tx_size_context_txfm_rect`). The 2:1 arm
(decode.rs:7660) and the 16x4 strip (`decode_rect4_16_strip`) already switched
on `INTRA_IN_INTER_MODE`; `decode_block_rect4`, `decode_block_rect64`,
`decode_block_rect` and (sweep) `decode_leaf_rect`, `decode_leaf_rect8` did
not.

Measured on the 2-frame cut (10-bit 1920x792, 128-superblock), decode-order
frame 1: the 32x8 `PARTITION_HORZ_4` strip at mi(48,176) read `tx_size_cat2`
row 1 where libaom reads row 2 (`EC_TXCTX ... above_px=16 left_px=32 ctx=1`
vs aomdec `ctx=2`). Ladder before: sustained divergence from mi(48,176).
Ladder after: exact through mi(40,221) (`tx_depth val=0 ctx=2 cat=1
rng=40539` == aomdec), ~230 more oracle symbols.

New rungs added so a ladder can see the symbol at all (this is what made r1's
bisection stop one block short): `EC_ISTEP ... name=tx_depth val= ctx= cat=`
in `decode_block_rect4` (cat 2), `decode_block_rect` (cat 2),
`decode_block_rect64` (cat 3), `decode_rect4_16_strip` (cat 1).

## NEXT DIVERGENCE (exact, do not re-bisect)

Block mi(40,222): strip 2 of a `PARTITION_VERT_4` of the 16x16 at mi(40,220)
(four 4x16 strips, cols 220..223; strip 0 inter, 1..3 intra-in-inter).
Everything through strip 1's luma TU matches. The first differing symbol is
strip 1's CHROMA `all_zero` (txb_skip):

| | ours | aomdec |
|---|---|---|
| plane 1 `all_zero` (entry rng=37582) | ctx base **1** -> rng **37384** | ctx **9** (= base 2 + chroma offset 7) -> rng **51992** |
| plane 2 `all_zero` | ctx base 1 -> rng 36800 | ctx 9 -> rng 33312 |

Same VALUES (1 then 0), different CDF ROW. Our chroma skip ctx is built at
`decode_rect4_16_strip`'s chroma call (`let skip_ctx = usize::from(around[plane].0)
+ usize::from(around[plane].1)`, decode.rs ~9480, feeding `read_coeffs_rect`
with `TxbSet::ChromaRect8x4`): the base is 1 where libaom's `get_txb_ctx`
gathers 2. The suspect is the chroma entropy-context map an INTER neighbour
writes (the strip's left/above chroma neighbour here is an inter block), i.e.
class `new-map-ignores-tile-edge` / `context-read-from-one-cell` on the chroma
side -- verify with `EC_DCDUMP`/`around_mi_rect` on the pair mi, and check
whether the inter chroma TU path records that map at all. Reproduce:

  systemd-run --user --scope -q -p MemoryMax=6G env EC_INTRA128_IN_INTER=1 \
    EC_TRACE_COEFF=1 <target>/release/examples/decode_probe \
